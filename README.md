# XML Scheme Generator

Локальное Windows-приложение для преобразования шаблонов из экспортированных SCADA-библиотек в графические XML-файлы `BufScadaPOUS`.

Приложение написано на Go, не использует Python и после сборки запускается как один автономный `XmlSchemeGenerator.exe`.

Подробные правила преобразования библиотеки, карточек, блоков, связей и SCADA XML-диалекта зафиксированы в [промежуточной семантике интерпретации шаблонов](TEMPLATE_INTERPRETATION_SEMANTICS.md).

## Быстрый запуск

1. При необходимости скопируйте `config.example.json` в `config.json` и задайте параметры целевого проекта. Без локального `config.json` используются безопасные значения по умолчанию.
2. Поместите XML-библиотеки в `libraries/`. Библиотека-пример уже включена.
3. Запустите `Start-XmlSchemeGenerator.cmd`.
4. Браузер откроет `http://127.0.0.1:3210`.
5. Выберите библиотеку и шаблон, задайте имя программного модуля POU и имя объекта, затем нажмите «Создать XML».
6. Результат появится в `output/` и будет доступен для скачивания в интерфейсе.

Если `.exe` отсутствует, стартовый скрипт сначала запускает тесты и собирает его установленным Go SDK.

## Как трактуется имя объекта

Имя программного модуля POU и имя экземпляра объекта — разные значения. Поле «Имя POU» записывается только в `OnePOU/@NAME` (например, `ADR_test`). Имя объекта (например, `_1110_LZIA_10101_ADR`) используется в `Block/@Info` и `ISACARDSINFO`. Если имя POU не передано через API, приложение формирует безопасное имя из шаблона, не используя имя объекта.

В режиме «Автоматически» приложение разрешает префиксы карточек через `ISAOBJLIST`. Например, для шаблона `ADR+AD3+HLB` ввод:

```text
_1110_LZIA_10101_ADR
```

распознаётся как карточка с префиксом `_ADR`, поэтому базовым именем станет `_1110_LZIA_10101`. Перед генерацией интерфейс показывает все производные имена: основной объект, `_ADR`, `_HLB`, `_MOS` и другие реально используемые выбранным шаблоном карточки.

Режим «Имя уже базовое» запрещает автоматическое снятие суффикса. Корневая часть PLC-идентификатора канонизируется в верхний регистр так же, как в экспорте SCADA; регистр шаблонных полей `.Out`, `.Stat` и других при этом сохраняется.

## Генерация

Поддержаны все типы примитивов, встречающиеся в восьми шаблонах библиотеки-примера:

- `31`, `34`, `35`, `36`, `37` → `Block`;
- `20` → `Link`;
- `1`, `2`, `7` → `OnePrim`.

Генератор:

- создаёт карточки только для фактически используемых `CARDID`;
- переносит `INITIALVALUE`, включая пустые значения и ведущий маркер `*`;
- сохраняет `CT=99` и маркеры ветвления `*` в маршрутах линий;
- переписывает все endpoint ID через новую карту `T11ID`;
- вычисляет рамку полилиний типа 7 по их `PointList`;
- формирует `FONTSTYLES`, `ISAOBJSINFO` и `ISACARDSINFO`;
- перед записью проверяет количество объектов, уникальность ID, ссылки и строгую корректность XML.

Перед сериализацией блоки стабильно упорядочиваются по зависимостям карточек: блок-владелец с пустым `T11Text` всегда записывается раньше блоков `.Field` с тем же `cardId`. Это правило применяется ко всем библиотекам, а не только к `AD3_v2`.

Файл записывается в лексическом диалекте экспортёра SCADA: UTF-8 с BOM, компактно, без форматирующих text-node, с self-closing пустыми элементами, физическими CRLF внутри графических `PARAMS` и без пустой optional-секции `FONTSTYLES`.

Выход всегда является корректным XML 1.0 UTF-8. Проприетарные байты `0x08`, найденные в старом экспортированном примере, намеренно не создаются.

## Важное ограничение транспортных ID

Из одной библиотеки и имени объекта невозможно узнать занятые ID, `Project`, `ControllerID`, `POU`, `KLPath` и другие значения конкретной проектной базы. Поэтому автономный режим выделяет внутренне согласованные транспортные `T11ID`, `cardId` и POU ID из `data/state.json`.

Перед импортом в существующий проект проверьте, поддерживает ли его импортёр переназначение ID. Если требуются уже существующие project-specific ID, задайте начальные значения в расширенных параметрах либо используйте дополнительный экспорт целевого проекта.

## Конфигурация

Скопируйте `config.example.json` в локальный `config.json`, чтобы изменить порт, значения `Common`, размер страницы, `GroupID`, `POUNum` и начальные диапазоны ID. Локальный файл исключён из Git, поскольку содержит параметры конкретной проектной базы. Если `config.json` отсутствует, приложение использует безопасные значения по умолчанию. `GroupID` и `POUNum` также можно переопределить для одной генерации в расширенных полях интерфейса. Сервер намеренно слушает только loopback-адрес `127.0.0.1`.
