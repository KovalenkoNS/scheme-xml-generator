# XML Scheme Generator

Независимое Windows-приложение для генерации XML SCADA: FBD, ST и HMI конкретного ПЛК. FBD строится по типам и шаблонам подключённой библиотеки. Приложение работает локально; получение IO через Host-client → Host-server → PostgreSQL подготовлено в интерфейсе, но действующий контракт ещё не подключён.

Поставка — автономный `XmlSchemeGenerator.exe` со встроенным веб-интерфейсом. Для запуска готового EXE Go и Node.js не нужны. Скачать готовый архив можно в [GitHub Releases](https://github.com/KovalenkoNS/scheme-xml-generator/releases/latest); Host использует тот же канал и проверяет соседний файл SHA256. [Руководство поставки](docs/distribution/README.md), [документация проекта](docs/README.md), [текущее поведение и API](docs/02-current-implementation.md). Фактическая проверка публикации и установки: [005](specs/005-github-delivery/verification.md).

## Быстрый запуск

1. Запустите `XmlSchemeGenerator.exe`. По умолчанию браузер откроет `http://127.0.0.1:3210`.
2. На основной странице подключите свою XML-библиотеку. Каталог покажет её типы и доступные шаблоны.
3. Перейдите на страницу **«Локальные данные»**, добавьте XLSX или подготовленную TXT-карту и выберите нужный ПЛК.
4. Укажите модель 715/850 и необходимые результаты **FBD / ST / HMI**. Внутри выбранных разделов задайте шаблоны, физические ModuleID и контекст целевого проекта.
5. Выполните генерацию. Результаты сохраняются в `output/`; их можно скачать или открыть кнопкой **«Просмотр»**.

Основная страница показывает фактическое соединение с Host; получение IO через БД пока не подключено. Локальные таблицы используются на второй странице; отдельных страниц AO, СКЗ и технологических объектов нет. Подключение библиотеки — отдельный компактный диалог основной страницы. Текущие постоянные настройки видны в интерфейсе.

Библиотеки можно также поместить в `libraries/` до запуска. Импорт через интерфейс принимает один XML до 512 МиБ, проверяет его перед подключением и не перезаписывает существующие файлы. Каталог может содержать тип без пригодного шаблона: такой тип не становится автоматически доступным для FBD.

## Источники и результаты

| Вид | Входы и существенные настройки |
|---|---|
| FBD | Назначения выбранного ПЛК и совместимые шаблоны подключённой библиотеки. Для модульного DO — числовые ModuleID и поддержанный профиль адресации |
| ST | TXT AO либо XLSX назначений AI/DI/DO; реальные физические ModuleID и профиль адресации |
| HMI | AO-карта или XLSX-инвентаризация; выбранный ПЛК и подтверждённый профиль диагностических кадров |

Для исходного `PS_IO_LIST_SCS_v4_new.xlsx` исправление008 отделяет прочитанные строки от профиля SCADA и добавляет раскрываемый просмотр по 25 строк с поиском, фильтром IO и обеими шкалами AI. Состав книги: **619 DI, 487 DO, 270 AI, 0 AO**; ещё401 строка без физического IO учитывается отдельно с причиной. Для AI владелец подтвердил Loop + `_main/_reserve` и отдельные Xin/Xs каждого физического канала. [Контракт источника и ограничения](docs/12-scs-io-source.md). Это описание изменений в исходниках; приёмка исправления установленного модуля пока NOT-RUN, [текущий отчёт](specs/008-real-io-workbook/verification.md).

NOT — независимая настройка инверсной логики DO; она не меняет выбранный шаблон и не определяется названием области. Тип системы РСУ/ПАЗ/СОГО не выбирает алгоритм генерации. Каждый физический ПЛК принадлежит одной из этих непересекающихся областей, имеет модель715/850 и собственные ST/FBD/HMI ([модель проекта](docs/11-project-domains.md)).

Текущие ограничения подтверждённых профилей: модульный DO FBD с диагностикой — 850, AO ST — 715, DI ST — 850, HMI — 715. AI/DO ST используют поддержанный профиль адресации. Образец `850_DIAG.xml` уже получен, но профиль HMI850 и связь SCS-источника с диагностическими кадрами пока не реализованы. Это ограничения реализации, а не аппаратный запрет или универсальная принадлежность ПЛК к области.

Для ST физический ID не выводится из имени модуля: `A1-02` не означает ID2. Значения должны соответствовать целевому проекту. Числовые ID физического оборудования и транспортные XML ID — разные сущности. Форматные примеры и правила резервов: [FBD/ST](docs/04-xml-formats.md), [HMI/XLS](docs/05-operator-interface-and-xls.md), [профили адресации](docs/08-controller-profiles.md).

Просмотр загружает фактически сохранённый XML. FBD показывает блоки и связи, ST — исходный код, HMI — доступную геометрию кадров. Поиск и навигация помогают перейти к сигналу или блоку; общий обзор вызывается отдельно. Для библиотечных HMI-символов возможны только границы без динамики. Просмотр и структурные проверки не подтверждают импорт или исполнение в SCADA.

## Данные и конфигурация

Рядом с приложением используются `libraries/`, `output/`, `data/state.json` и `logs/`. Необязательный `config.json` задаёт параметры запуска и начальный контекст XML; [config.example.json](config.example.json) — пример, который следует сверить с реальным проектом. Пользовательские библиотеки, таблицы, настройки и состояние ID не входят в архив поставки.

```powershell
./XmlSchemeGenerator.exe -root 'C:\SCADA\Generator' -port 3210 -no-browser
```

Новый результат получает свободное имя и не перезаписывает предыдущий файл. Изменение формы не меняет уже сохранённый XML. Локальные курсоры ID не знают занятые номера в SCADA; несколько процессов с одним корнем не координируются. Границы восстановления после ошибок описаны в [текущей реализации](docs/02-current-implementation.md#6-состояние-запись-и-восстановление).

## Разработка и API

Новые изменения выполняются через GitHub Spec Kit в VS Code: [SDD](docs/SDD.md), [обязательные правила](.specify/memory/rules.md), [карта исходников](docs/SOURCE_LAYOUT.md). Предметная модель отделена от входных адаптеров, HTTP, адресации и генераторов. Тесты и фикстуры находятся в `tests/`.

Приёмка выполняется только на фактически установленном стандартном модуле, скачанном Host из GitHub и запущенном им при действующем соединении Host-client → Host-server → PostgreSQL. Исходный IO-лист и библиотека остаются неизменными; разрешённые изменения пользовательских настроек сохраняются в резервной копии и восстанавливаются после сценария. Верификация охватывает AI/AO/DI/DO и подтверждённые профили FBD/ST/HMI.

Изолированные каталоги, новые проверочные профили, тестовые модули и альтернативная проверка при недоступности установленного ПО запрещены. Существующие инструменты `tests/` сохраняются как история; прежний изолированный `verify-directions.cjs` не является командой текущей приёмки. Перед итоговым ответом отдельный subagent проверяет все 12 пунктов [checklist Host](../../Develop/Host-client/checklist.md); любой незакрытый пункт означает отказ приёмки. Процесс: [008-real-io-workbook](specs/008-real-io-workbook/spec.md).

Для компиляции нужны Go 1.24+ и PowerShell; Node.js используется инструментами разработки. [build.ps1](build.ps1) теперь только собирает EXE с `CGO_ENABLED=0`, `-trimpath` и `-ldflags='-s -w -H windowsgui'`, без запуска тестов или изолированного приложения. Windows GUI subsystem исключает отдельную консоль при старте готового EXE. `Start-XmlSchemeGenerator.cmd` использует существующий EXE, а при его отсутствии вызывает сборку. После изменения исходников или веб-ресурсов нужна явная пересборка и поставка стандартного модуля через GitHub; компиляция не закрывает приёмку установленного ПО.

Активный FBD API — `/api/generate` и `/api/generate/library-do`, назначения ST — `/api/mappings/generate`. Прежний `/api/temporary/ao/generate` и режимы `fbd`/`fbd-native-do` в `/api/mappings/generate` и его историческом alias `/api/skz/generate` возвращают `410`, без резервирования ID и создания файлов. Встроенного запасного FBD-профиля нет. Полная таблица маршрутов и формы данных — в [главе 02](docs/02-current-implementation.md#4-http-api-действующие-маршруты).

История прежних интерфейсов и профилей остаётся в [карточках задач](docs/tasks/README.md) и [ADR](docs/decisions/README.md); это не инструкция для текущего интерфейса. Правила библиотечного XML описаны в [семантике шаблонов](TEMPLATE_INTERPRETATION_SEMANTICS.md). Проверки текущих изменений: [пакет 003](specs/003-unified-workspace/verification.md), [пакет 004](specs/004-semantic-layout/verification.md).
