# Полная проверка

`go test ./...` запускает открытые API-проверки и драйвер `TestWhitebox`. Все тестовые исходники находятся в этом каталоге. `fixtures/<предмет>/` содержит перенесённые исходные фикстуры; production-пакеты их не встраивают.

Исторические тесты внутренних алгоритмов лежат в `whitebox/<путь production-пакета>`. Вложенный `go.mod` исключает их из самостоятельной компиляции: они не являются отдельными реализациями пакетов. Драйвер создаёт временный Go `-overlay`, добавляющий только `_test.go` к реальным исходным пакетам. Production-файлы не копируются, не перекрываются и не сохраняются второй версией. Дочерний вызов перечисляет только предметные пакеты, использует `-count=1 -p 1` и не может снова запустить драйвер.

Драйвер читает инвентарь и содержимое исходников, тестов, встроенных ресурсов и локальных фикстур, чтобы внешний кэш зависел от входов дочерних проверок. Для принудительного полного повторения: `go test ./... -count=1`. Фикстуры пользовательских библиотек остаются необязательными; отчёт должен отличать выполненный smoke от Skip.

Генераторные whitebox-пакеты получают через временный `TestMain` прежний рабочий каталог `internal/generator`, чтобы сохранить смысл относительных пользовательских путей. Ссылки на версионируемые образцы перенесены в `tests/fixtures`. Тестовый `fbd/dispatch_test.go` маршрутизирует смешанные исторические ST/FBD-проверки в те же общие планировщики и предметные генераторы, не экспортируя приватные валидаторы и не копируя алгоритмы генерации. Повторённые между тестовыми пакетами маленькие фабрики фикстур — только тестовые данные.

Дополнительные проверки: `node --test tests/sdd/sdd.test.cjs tests/web/workspace-model.test.cjs tests/preview/parser.test.cjs`, реальные browser-сценарии в `tests/web` и `tests/preview`. `go run ./tools/rulescheck` проверяет физическую структуру, разделение тестов и наличие комментариев; предметный смысл комментариев и границ требует review.

Обязательная сквозная матрица XML-006: после `build.ps1` выполнить `node tests/web/verify-directions.cjs`. Проверяет AI/AO/DI/DO × FBD/ST/HMI на поддержанных профилях; для каждого источника различает два ПЛК и сверяет сохранённый файл с просмотром. По умолчанию запускается корневой `XmlSchemeGenerator.exe`, другой путь задаётся через `GENERATOR_EXE`. Нужны локальная полная библиотека, Chromium и Python3; отсутствующий вход не заменяется Skip. Все данные проверки и доказательства, включая SHA256 EXE, записываются только в `.artifacts`.
