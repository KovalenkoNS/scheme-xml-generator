# Внешние проверки генерации

`fbd/inversion_test.go` проверяет инверсию связи BOOL → D32 в библиотечном шаблоне, границы отказа и отсутствие изменений allocator/output при ошибке HTTP. `fbd/library_do_test.go` проверяет модульную сборку: 32 сигнала — один D32, одна цепь Quality/QUAL_STAT; несколько модулей, пропуски, смешанная инверсия, реальные ISA-номера библиотеки и запись через HTTP.

```powershell
go test ./tests/generator/... -count=1 -v
```

`st/inputs_test.go` создаёт синтетические предметные планы; `st/planning_test.go` проверяет ограничения выбора и физические ID; `st/rendering_test.go` — полный ST; `st/reference_test.go` — реальные таблицы и независимые эталонные назначения. Каталоги FBD и ST имеют разные ответственности и не смешивают старый fixed-FBD с текущим выводом.

Тесты обращаются к публичным API, читают минимальные синтетические библиотеки и используют временные каталоги. Два дополнительных сценария читают `libraries/all_lb_sinopec.xml`, если пользовательский файл присутствует; отсутствие отмечается `Skip`. Библиотека не изменяется и не включается в репозиторий. Структурные проверки не означают импорт/исполнение SCADA.
