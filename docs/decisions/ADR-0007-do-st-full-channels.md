# ADR-0007 · DO ST: все физические каналы через D32V

- Дата: 28.09.2026.
- Статус: принято владельцем: «Да, все 32 канала через D32V».
- Источник и проверки: [TASK-0009](../tasks/TASK-0009-do-st-full-channels.md).

## Контекст

После генерации B03 владелец обнаружил, что A33-08 содержит только каналы 0…27. Причина — прежнее правило одного DO ST-присваивания на перечисленное сопоставление Excel. Полный физический модуль имеет 32 выхода; отсутствие технологического тега не должно удалять физическую ST-привязку. Отдельно подтверждено сохранение промежуточных объектов D32V, а не переход к прямым присваиваниям из Tag No.

## Решение

DO ST каждого исходного и дополнительного модуля создаёт ровно 32 присваивания для каналов 0…31. Правые части — выходы D32V._00…_31. Правило применяется к raw IO и подготовленным DO-перекладкам, CPU715 legacy и поддержанным профилям CPU850. FBD по-прежнему подключает только технологические источники из карты, не создавая вымышленных BOOL-резервов.

Сопоставления карты остаются неизменными; физические каналы считаются отдельно для лимита 4096 и статистики ST. DO даёт 32 присваивания/модуль, DI сохраняет 33, AI — два на перечисленный канал. Повторы логических DO-источников считаются по исходным сопоставлениям.

Это уточняет физическую часть [ADR-0006](ADR-0006-raw-do-source-and-placements.md), не меняя Tag No + `_DDVH`, четыре размещения, разделение ПЛК и правила DI. Исторические числовые результаты TASK-0007/0008 не переписываются; новые результаты фиксируются в TASK-0009.

## Границы

Старые пользовательские XML не перезаписываются; для нового полного ST нужна повторная генерация с реальными ModuleID. Перед совместным импортом проверяются непересекающиеся POUNum. Автотесты не подтверждают импорт, порядок исполнения или состояние аппаратных выходов в SCADA.
