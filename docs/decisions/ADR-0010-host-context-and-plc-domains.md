# ADR-0010 · Контекст Host и независимые измерения модели ПЛК

- Статус: **ПРИНЯТО в указанной ниже части; уточнения открыты**.
- Дата: 29.09.2026.
- Источник: ответы владельца при повторной проверке файлов контекста.
- Пакет: [002-context-clarification](../../specs/002-context-clarification/spec.md); связанный владелец поведения Host — [004-module-context](https://github.com/KovalenkoNS/Host-client/blob/main/specs/004-module-context/spec.md).

## Принятые ответы

1. «Host должен читать контекст и записывать вопросы и результаты» — целевая обязанность Host-client как оркестратора. На вопрос об авторах — приложения, ИИ внутри Host и пользователь — ответ: «Все перечисленные». На вопрос о Markdown/SDD приложений и контексте рабочего инженерного проекта: «Оба вида, раздельно». Конкретные схемы, права и машинный протокол не выбраны.
2. «Host является оркестратором и управляет всеми доступными приложениями, выходные данные модулей настраиваются самими модулями». Здесь модуль — управляемое приложение; это не модуль физического I/O ПЛК. Host не становится владельцем предметных настроек выходных данных генератора.
3. 715 и 850 — разные версии/модели ПЛК. ПАЗ, РСУ, СОГО — обозначения фактической области их работы, а не названия моделей. Область не определяет модель, модель не определяет область.
4. ST, FBD, HMI — внутренние файлы/элементы описания SCADA. Оба вида ПЛК и все области их применения содержат эти элементы; у каждого экземпляра ПЛК они независимы. Пример владельца: РСУ содержит PLC715 и PLC850, у каждого собственные ST/FBD/HMI.
5. «ПЛК всегда относится только к одной области»; РСУ/ПАЗ/СОГО — главные **строго непересекающиеся множества**, внутри каждого находятся ПЛК. Представление — [круги Эйлера](../11-project-domains.md). Модель CPU — свойство экземпляра внутри области, а не пересекающее области множество.
6. Приложения должны иметь возможность запрашивать данные у Host. Host-client — поставляемое распространяемое приложение для оркестрации модулями и данными между сервером и модулями. Host-server отвечает за хранение и маршрутизацию IO-листов всего SCADA-проекта; связь с PostgreSQL и авторизация проходят через сервер. Это уточняет принятую топологию, не вводя прямого доступа модулей к БД.
7. Представление IO-листов на сервере — «Только структурированные записи БД». В первой версии операции модулей — «Только получение данных»: без загрузки новых версий и правки отдельных записей. Это ограничение IO-листов, не запрет Host записывать вопросы/результаты в контекст. Источник первичного наполнения и механизм версий ещё открыты; существующие локальные файлы генератора не удаляются.
8. Дополнительное правило владельца: если запрос агенту противоречит описанным правилам и контексту, агент уведомляет пользователя и просит уточнение. [Инструкции](../../AGENTS.md) требуют конкретного расхождения со ссылкой, приостановки только зависимой части и фиксации ответа; молчаливая отмена правила не допускается.

## Последствия и пределы

Требуемая модель и текущая полнота генератора различаются. Ожидание эталона HMI850 или отсутствие поддержанного профиля DI715 в коде означает пробел реализации/доказательств, а не отсутствие HMI/ST/FBD у соответствующего ПЛК.

[ADR-0005](ADR-0005-paz850-no-ao.md) остаётся правилом конкретной ранее указанной ПАЗ без AO. Его нельзя расширять на все CPU850 или на все области РСУ/СОГО. Существующий отказ AO850 по типу CPU описывается в документации как текущее ограничение реализации; поддержка других комбинаций не добавляется этой записью. Правила NOT/Quality [ADR-0008](ADR-0008-do-paz-native-fbd.md) также относятся к указанному профилю.

Определены непересекающиеся области и единственная принадлежность ПЛК; все три источника вопросов/результатов; два раздельных вида контекста. Открыты конкретная схема идентификаторов/хранения, версии контекста и IO-листов, права изменения, машинный интерфейс приложения и развёртывание. Точные версии SCADA и библиотек ответом о моделях ПЛК не заданы.

Исторические TASK и ADR сохраняются. Чтение/запись контекста Host и универсальная поддержка всех профилей генератора не объявляются реализованными.
