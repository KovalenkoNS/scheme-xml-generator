# ADR-0003 · Закрытая SCADA: обмен только XML-файлами

- Статус: **ПРИНЯТО владельцем проекта**.
- Дата: 25.09.2026.
- Источник: уточнение владельца в задаче документации: «Scada система закрыта, единственный способ взаимодействия с ней — экспорт/импорт .xml файлов».
- Область: внешнее взаимодействие с целевой SCADA; требование R-016.
- Задача: [TASK-0002](../tasks/TASK-0002-scada-xml-boundary.md).

## Решение

SCADA — закрытая внешняя система. Единственный доступный способ обмена с ней — экспорт и импорт `.xml` файлов. Генератор получает доступные сведения о её проекте из переданных XML-экспортов и формирует XML для импорта. Прямой API, SDK, чтение или изменение внутренней БД SCADA и программные уведомления от неё не входят в доступные способы взаимодействия.

Принятая цепочка **приложение ↔ orchestrator ↔ сервер ↔ PostgreSQL** описывает собственную систему подготовки данных и генерации. Её внутренние протоколы остаются отдельным вопросом. PostgreSQL в этой цепочке нельзя считать внутренней БД SCADA или способом обхода файловой границы.

```mermaid
flowchart LR
    A["Приложение / подготовка контекста"] --> OUT["Сгенерированный XML"]
    OUT -->|"импорт файла"| C["Закрытая SCADA"]
    C -->|"экспорт файла"| IN["XML состояния / примера проекта"]
    IN --> A
```

Схема задаёт допустимую границу обмена. Она не утверждает, что уже реализованы автоматическая доставка, универсальный разбор проекта или сравнение повторного экспорта.

## Последствия для генерации и проверки

1. Контракт каждого XML-профиля уточняется по экспортам, версиям среды и наблюдаемым результатам импорта. Нужно документировать, какие сущности и связи доступны в экспорте, а какие сведения отсутствуют.
2. Контекст связывается с конкретным XML-файлом, его происхождением, датой, версией SCADA и областью проекта. Экспорт является снимком; он не доказывает актуальное состояние проекта после последующих изменений.
3. Статусы «сгенерировано», «проверено структурно», «импортировано» и «проверено при исполнении» различаются. Ответ собственного сервера или успешная запись файла не подтверждают импорт в SCADA.
4. Повторный XML-экспорт может подтверждать состав и сохранённые привязки в пределах экспортируемых данных. Он сам по себе не доказывает компиляцию, выполнение логики или поведение оборудования. Наблюдения инженера оформляются в [протоколе](../templates/import-report.md); это запись человека, а не программный ответ SCADA.
5. Получение файлов, исполнитель импорта/экспорта и возможная автоматизация этих файловых операций пока неизвестны. Ограничение не означает автоматически ни ручной режим всех действий, ни возможность их автоматизации.
6. Выгрузка XLS технологических объектов остаётся существующей, ранее принятой функцией. Прямой импорт XLS в целевую SCADA не следует из нового ограничения. Получатель XLS, его промежуточная роль и возможная потребность в XML для технологических объектов требуют отдельного ответа. Конвертер XLS → XML и удаление XLS этим решением не утверждаются.
