# ADR-0008 · Отдельный DO FBD ПАЗ с NOT и диагностикой

- Статус: принято по нативному примеру и уточнениям владельца.
- Дата: 28.09.2026.
- Задача: [TASK-0010](../tasks/TASK-0010-do-native-fbd.md).

## Основания

`DO_FBD_example.xml` содержит цепи BOOL → NOT → D32V и физическое Quality → QUAL_STAT → sts. Подготовленная книга содержит `простой` и `DO-1`, а нативный A70 — только DO-1. Владелец уточнил: «Все DO через NOT» и «not в данном случая является инверсной логикой ПАЗ». Диагностика использует канал 0 физического модуля. На вопрос префикса экземпляров ответ: «Всегда использовать имя ПЛК».

## Решение

1. Явный профиль `native850` применяет NOT ко всем DO ПАЗ, независимо от шаблона и I/O Type строки. Обычный `software` остаётся без инверсии.
2. Новый профиль требует только DO, CPU850, Measurement/Quality и явные ModuleID. Диагностика `_IO_I<ID>_DO32P_0_VAL_DIAG.Quality` подключается через QUAL_STAT к `sts`.
3. Подготовленная карта использует точный RHS `SCS DO`, а не догадку по Марка/Loop. Исходный PS_IO_LIST сохраняет Tag No + `_DDVH`.
4. Имена D32V — `_<SCS>_<Module>` для согласования FBD/ST; шкаф не переименовывает ПЛК.
5. ST сохраняет все 32 выхода через D32V. NOT добавляется только в FBD, свободные каналы не получают вымышленных BOOL.

## Последствия

Разделены обычная логика DO и инверсная ПАЗ. Новый FBD требует физических ID, в отличие от программного старого. Документы по-прежнему разделяются по ПЛК. Числа ID и POUNum из примера не гарантируют соответствие целевому проекту. Импорт/компиляция/исполнение требуют отдельного протокола. Полная модель — [глава10](../10-do-paz-native-semantics.md).
