# ADR-0001 · Документация как основной интерфейс работы

- Статус: **ПРИНЯТО**.
- Дата фиксации: 25.09.2026.
- Источник: текущий запрос владельца проекта о создании папки документации, формализации задачи, высокой полноте контекста, вопросах в документах и первичном ответе документацией.

## Контекст

Проект продолжается между сессиями и устройствами. Правила генерации, уточнения инженера и результаты импорта не должны зависеть от памяти отдельного диалога. Целевая интеграция с orchestrator, сервером и PostgreSQL требует явного контракта знаний, а не только передачи таблиц.

## Решение

1. Хранить рабочую документацию в `docs/` внутри проекта.
2. Сначала фиксировать задачу, известные данные и вопросы в документах; итог работы также фиксировать там.
3. Каждое неизвестное, влияющее на подзадачу, оформлять вопросом с ID, ожидаемыми сведениями и полем ответа.
4. Принятые ответы хранить с источником и областью действия; не выдавать предложения за ответы.
5. Поддерживать наглядные схемы архитектуры и каждого типа XML рядом с подробными правилами.
6. В чат передавать краткое сообщение и ссылки на самодостаточные документы/артефакты.

## Последствия

В корне создан [AGENTS.md](../../AGENTS.md), задающий этот порядок будущим программным агентам. Изменение генерации сопровождается изменением связанных спецификаций и карточки задачи. Правило не вводит повторного подтверждения уже разрешённой работы и не требует одновременно закрыть все вопросы будущей интеграции.

Автоматическое чтение/запись документации orchestrator или БД пока не реализовано; формат такой синхронизации остаётся Q-CTX-001. Markdown является текущим рабочим носителем, HTML — визуальным обзором.

## Проверка соблюдения

Для завершённой задачи есть карточка, источники, результат, проверка, открытые вопросы и ссылки. Документы позволяют следующему исполнителю продолжить без обязательного чтения прежнего чата.
