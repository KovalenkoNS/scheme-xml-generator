# ADR-0006 · DO из исходного IO: Tag No и четыре размещения

- Дата: 28.09.2026.
- Статус: имя DO и сохранение DI приняты владельцем; развёртка размещений реализована по явным полям исходной книги и существующей модели DO. Результаты проверки — в карточке задачи.
- Источник: [TASK-0007](../tasks/TASK-0007-raw-do-excel.md), ответы «Да, добавить DO и сохранить DI» и «Tag No + `_DDVH`».

## Контекст

Исходный `../XML dev/PS_IO_LIST_SCS_v4_new.xlsx` относительно корня проекта содержит DI и DO. В TASK-0006 подтверждены DI C1/C2; последующее уточнение добавляет обработку DO, сохраняя эти правила. В 250 из 487 DO-строк `Loop` отличается от `Tag No`, поэтому выбор источника имени нельзя выводить из сходства соседних полей. Подготовленные колонки D32 в этой книге пусты.

## Решение

Для исходных DO-строк имя управляющей BOOL-переменной строится из `Tag No`: `-` заменяется на `_`, добавляются начальное `_` и суффикс `_DDVH`. Пример строки2 — `_3101_XZY_60507_DDVH`; значение `Loop` с XZV не заменяет имя XZY. Это правило исходной IO-книги. Подготовленные AI/DO-перекладки продолжают использовать буквальные имена из своих выражений; добавлять им суффикс автоматически нельзя.

Каждое явное размещение в `Main_module`, `Main_module2`, `Redundant_module`, `Redundant_module2` получает тот же логический источник и исходный `Channel`. Повтор источника на разных физических позициях разрешён: FBD использует одну карточку BOOL и отдельные ссылки `BOOL.0 → D32V.iNN`; ST пишет `D32V._NN` в физический выход. Один модуль в нескольких полях одной строки и конфликт разных источников на одной позиции отвергаются. Полностью совпадающее назначение в повторной строке объединяется с предупреждением. `SCS` задаёт ПЛК и отдельное пространство имён, номера каналов не уплотняются.

Один владелец сопоставляется без учёта регистра; все графические BOOL-ссылки, в том числе из разных POU, используют точное написание `Card.Info` его общей карточки. Это сохраняет разрешимость ссылок при разных вариантах регистра имени источника.

Поддержанные исходные типы DO — `DOR-P`, `DOR-VFC`, `DOR (SCS3)`. Неизвестные DO-типы, пустые либо неподтверждённые резервные имена не превращаются в выдуманные теги: запрос отклоняется. В предоставленных DO-строках нет SPARE или пустого Tag No. Правило DI SPARE не переносится на DO.

DI сохраняет собственные правила: Main_module → C1, Redundant_module → C2 одного DDR, без `_DDVH` и без LZS → LZSA. Вторые пары Main_module2/Redundant_module2 для DI остаются неподдержанными. Пользователь может выбрать только DO, только DI или обе группы; результат разделяется по SCS, по одному XML на выбранный ПЛК.

## Последствия и проверка

Последующее уточнение: [ADR-0007](ADR-0007-do-st-full-channels.md) требует все 32 физических DO-присваивания каждого модуля, независимо от количества перечисленных логических сопоставлений. Правила имён, FBD и четырёх размещений настоящего ADR сохранены.

487 DO-строк содержат четыре разных размещения каждая: 1948 подключений, 72 модуля, 12 групп и 3 ПЛК. Вместе с DI — 3184 подключения, 122 модуля и 20 групп. Контрольные составы FBD/ST приведены в [главе04](../04-xml-formats.md); факт прохождения проверок записывается в TASK-0007.

Доступность профилей CPU715/850, запрет AO850 в целевой ПАЗ и отсутствие подтверждённого HMI850 не меняются. Выбранный физический профиль и ModuleID сверяются с конфигурацией назначения. Автоматические проверки не подтверждают импорт и исполнение в SCADA.
