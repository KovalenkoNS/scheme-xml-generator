# ADR-0009 · Единый GitHub Spec Kit и независимость проектов

- Статус: **ПРИНЯТО** — формат и границы заданы владельцем; выполнение миграции отражено в пакете ниже.
- Дата фиксации: 28.09.2026.
- Источник: сообщения владельца о едином SDD для XML sandbox и Develop, разделении проектов и выборе GitHub Spec Kit в VS Code.
- Пакет изменения: [001-unified-sdd](../../specs/001-unified-sdd/spec.md).
- Заменяет: требования к расположению новых постановок и карточек в [ADR-0001](ADR-0001-documentation-first.md); остальные правила ADR-0001 сохраняются.

## Контекст

Генератор использовал `docs/tasks/TASK-*.md`, тогда как другие отдельные проекты имели собственные способы ведения спецификаций. Общий формат нужен для продолжения работы без восстановления чата и без разных активных источников одного требования.

## Решение

1. Применяется GitHub Spec Kit v1.0.12 с общим [процессом SDD](../SDD.md), локальной [конституцией](../../.specify/memory/constitution.md) и одним пакетом `specs/<NNN-slug>/` на новое изменение.
2. Канонические файлы пакета: `spec.md` — требования и приёмка; `plan.md` — проектирование; `tasks.md` — исполнение; `verification.md` — проверка с доказательствами. Последний файл — общая договорённость проектов поверх Spec Kit.
3. Host-client является оркестратором; Host-server отвечает за авторизацию клиентов и маршрутизацию; xml-generator является независимым ПО генерации XML SCADA. Общий процесс не объединяет продукты, репозитории, сборки и жизненные циклы.
4. Межпроектное изменение оформляется локальными пакетами затронутых проектов со ссылками на владельца контракта. Принятие ролей не является доказательством подключения компонентов.
5. Исторические TASK-0001…0010 и ADR-0001…0008 сохраняются на прежних путях. Незавершённое продолжение получает новый пакет со ссылкой на историю; прошедшие проверки и статусы не переоцениваются автоматически.
6. `docs/` сохраняет предметные правила XML, текущее поведение, реестры вопросов, решения и протоколы. Пакет ссылается на эти источники и фиксирует изменение, не создавая вторую независимо редактируемую копию требования.

## Последствия и проверка

Обновлены входные правила и указатели на новый процесс. Структурная проверка XML по-прежнему не доказывает импорт или исполнение в закрытой SCADA; [ADR-0003](ADR-0003-scada-xml-boundary.md) сохраняется. Протоколы интеграции и автоматическая синхронизация документов не реализуются этим решением. Проверки миграции находятся в [verification.md](../../specs/001-unified-sdd/verification.md).
