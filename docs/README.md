# Документация генератора SCADA

Редакция процесса: 28.09.2026. Основной язык: русский. Этот каталог — долговременный предметный контекст проекта. Новые изменения ведутся по [единому SDD на GitHub Spec Kit](SDD.md) в пакетах `specs/<NNN-slug>/`; исходные карточки сохраняются в [истории задач](tasks/README.md).

**Цель проекта:** независимое ПО xml-generator генерирует FBD- и ST-POU, а также операторский интерфейс SCADA из согласованных исходных данных. В целевой цепочке **xml-generator ↔ Host-client ↔ Host-server ↔ PostgreSQL** Host-client является оркестратором, Host-server отвечает за авторизацию клиентов и маршрутизацию. Проекты разделены; протоколы интеграции ещё требуют уточнения. Сегодня генератор работает локально с файлами. Источник уточнения ролей — [ADR-0009](decisions/ADR-0009-unified-spec-kit.md).

**Принятая граница SCADA:** система закрыта; единственный способ взаимодействия с ней — экспорт/импорт `.xml` файлов. Внутренняя цепочка получения данных рассматривается отдельно. Последствия и оставшиеся вопросы зафиксированы в [ADR-0003](decisions/ADR-0003-scada-xml-boundary.md) и [TASK-0002](tasks/TASK-0002-scada-xml-boundary.md).

## Как читать утверждения

| Метка | Значение | Что является основанием |
|---|---|---|
| **РЕАЛИЗОВАНО** | Поведение найдено в текущем коде | Ссылка на исходник, при необходимости тест |
| **ПРИНЯТО** | Владелец явно задал требование/ответ | Запись решения с источником |
| **ПРЕДЛОЖЕНИЕ** | Вариант будущего устройства | Требует решения; не считается работающей функцией |
| **НЕИЗВЕСТНО / ТРЕБУЕТСЯ** | Нет достаточных сведений | Открытый вопрос с ожидаемым ответом |
| **ПРОВЕРЕНО СТРУКТУРНО** | Проверена генерация/сериализация/ссылки | Автоматическая проверка или разбор XML |
| **ПОДТВЕРЖДЕНО ИМПОРТОМ** | Результат проверен в целевом ПО | Протокол импорта с окружением и артефактом |

В главе 02 описание текущего кода — факт на дату редакции. Архитектурные контракты главы 03 — предложения, если рядом не отмечено прямое требование владельца. Числа из контрольных Excel — свойства конкретных примеров, не универсальные ограничения оборудования.

## Где отвечать на вопросы

У каждого вопроса есть ID. Ответ записывается рядом с вопросом вместо `[ТРЕБУЕТСЯ ОТВЕТ]`, затем добавляются автор/роль, дата, источник и статус. Если сведения неприменимы, требуется явное `неприменимо` с объяснением. Пустое поле и «по умолчанию» без источника не закрывают вопрос.

Обязательность относится к **затрагиваемой подзадаче**: вопросы PostgreSQL не блокируют документирование существующего XML, но блокируют реализацию соответствующего контракта БД. Не требуется сразу ответить на весь реестр, чтобы продолжать независимую работу.

- Первичный источник текущего поведения — [код](../internal/) и соответствующие тесты.
- [README приложения](../README.md) содержит запуск, форматы запросов и пользовательские сценарии.
- [Семантика шаблонов](../TEMPLATE_INTERPRETATION_SEMANTICS.md) и [семантика IO-диагностики](../DIAGNOSTIC_IO_SEMANTICS.md) сохранены на прежних местах: это подробные источники и история проверенных решений.
- Примеры SCADA/XML и таблиц являются доказательствами для конкретного профиля. Один пример не доказывает совместимость всех версий SCADA или типов ПЛК.
- Для будущих задач действует [AGENTS.md](../AGENTS.md). Реестр ответов, спецификации и карточка задачи обновляются вместе с поведением ПО.

Текущий пакет создан в рамках [TASK-0001](tasks/TASK-0001-documentation-baseline.md). EXE и алгоритмы генерации этой задачей не изменяются.
