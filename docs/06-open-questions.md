# 06. Реестр недостающего контекста и обязательных вопросов

Дата открытия: 25.09.2026. Вопросы с незаполненным ответом **ОТКРЫТЫ**; известная часть записывается со статусом **ЧАСТИЧНО ОТВЕЧЕН**, а оставшиеся сведения продолжают требоваться для зависимой подзадачи. Статус и источник каждого ответа указаны рядом с вопросом. Это не утверждение, что ответы нигде не существуют: нужные знания пока не представлены в проверенном контексте проекта.

## 1. Правила заполнения

1. Найти вопрос по ID; вписать ответ в последнюю колонку либо добавить под соответствующей таблицей блок `Ответ Q-…`.
2. Для каждого ответа указать: **значение/решение; автор или ответственная роль; дата; источник (документ, экспорт, схема, пример); область действия; статус принятия**.
3. Файл, пример или схема должны иметь устойчивую ссылку и версию. Чувствительные реквизиты подключения не помещать в документацию: достаточно описания способа получения и имени конфигурационной ссылки.
4. Если ответ зависит от версии SCADA, CPU или проекта, перечислить варианты. Не распространять ответ одного профиля на все остальные.
5. Закрывать вопрос статусом `ОТВЕЧЕН`, `ПРИНЯТО` или `НЕПРИМЕНИМО — причина`. При неполном ответе использовать `ЧАСТИЧНО ОТВЕЧЕН` и перечислять недостающие сведения. Наличие предложения не закрывает вопрос. Противоречивые сведения получают статус `КОНФЛИКТ` с обеими версиями.
6. До ответа нельзя принимать решение в **зависимой подзадаче**, указанной в таблице. Независимая работа продолжается. Это не запрос разрешения на все действия и не требование ответить сразу на весь документ.

Пример оформления ответа:

```text
Ответ Q-INT-001
Статус: ОТВЕЧЕН / ЧАСТИЧНО ОТВЕЧЕН / ПРИНЯТО / КОНФЛИКТ / НЕПРИМЕНИМО
Значение: [ТРЕБУЕТСЯ]
Автор / ответственная роль: [ТРЕБУЕТСЯ]
Дата: [ТРЕБУЕТСЯ]
Источник и версия: [ТРЕБУЕТСЯ]
Область действия: [ТРЕБУЕТСЯ]
Затронутые требования / задачи / документы: [ТРЕБУЕТСЯ]
```

### Полученное уточнение от 25.09.2026

**ПРИНЯТО; автор — владелец проекта; источник — сообщение в задаче документации:** «Scada система закрыта, единственный способ взаимодействия с ней — экспорт/импорт .xml файлов». Область действия — внешняя граница целевой SCADA, решение [ADR-0003](decisions/ADR-0003-scada-xml-boundary.md), требование R-016.

Прямой API, SDK и доступ к внутренней БД SCADA не рассматриваются как доступные способы обмена. Протоколы собственной цепочки app ↔ orchestrator ↔ server ↔ PostgreSQL остаются открытым вопросом. Исполнитель файловых операций, их автоматизация, полнота экспортируемых данных и достаточные доказательства импорта не определены этим ответом. Уточнение частично отвечает на Q-OPS-004, Q-SCOPE-005 и Q-APP-006; их оставшиеся части сохранены ниже и в главе 02.

## 11. Минимальная последовательность заполнения

1. Определить участников и требуемые результаты: Q-SCOPE-001…005.
2. Описать реальный orchestrator/server и доступную модель БД: Q-INT-001/002, Q-DB-001/002.
3. Зафиксировать источник каждого инженерного поля и правила конфликтов: Q-DATA-001/002/006.
4. Согласовать один сквозной профиль, его контекст и эталонный импорт: Q-GEN-001/002/003, Q-ACC-001/002.
5. Закрыть оставшиеся вопросы, необходимые для реализации именно этого профиля. Остальные сохранять открытыми с привязкой к следующему этапу.

Конкретная следующая задача интеграции пока **ожидает информации**, а задача создания документационной базы может быть завершена независимо от ответов.
