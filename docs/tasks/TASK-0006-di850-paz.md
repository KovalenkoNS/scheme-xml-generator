# TASK-0006 · DI ПЛК 850 по нативным FBD/ST; AO в ПАЗ отсутствует

- Статус: Выполнена — DI Excel подключён к parser/API/UI; импорт и исполнение в SCADA ещё не проверены.
- Дата: 28.09.2026.
- Источник: владелец предоставил `DI_850_FBD.xml`, `DI_850_ST.xml` и уточнил: «850 ПЛК использует система ПАЗ в которой нет AO».
- Исполнитель: программный агент.
- Связанные документы: [TASK-0005](TASK-0005-dual-plc-support.md), [матрица профилей](../08-controller-profiles.md), [Q-XML-007](../04-xml-formats.md).

## Запрос и ожидаемый результат

Использовать новые нативные XML для реализации DI850 и исправить прежнее ожидание AO850. Для целевой системы ПАЗ AO отсутствует: это неприменимый режим, а не недостающий профиль. Правило относится к заданному проекту/системе, не является утверждением об аппаратных возможностях всех CPU850.

Критерии: восстановить направления связей DI, ST-формулы качества/значения, имена модулей и каналов; реализовать согласованный путь ввода и генерации; не ломать AI/DO и CPU715; тестами проверить ссылки, транспортные ID и отсутствие побочных эффектов при ошибках. Импорт и исполнение в SCADA проверяются отдельно.

## Исходный контекст

- Исходники содержат незакоммиченные результаты TASK-0004/0005 поверх `a1752aa`; они сохраняются.
- Новые файлы находятся в соседнем каталоге `../XML dev/`, а не в `scheme-xml-generator/XML dev/`.
- Предварительно в ST найден CPU850, POU `DI_A11_channels`, физические обращения `_IO_I<ID>_DI32_<channel>_VAL.Measurement` и `ANY_TO_DWORD(QUAL_STAT(...Quality))` в `.Stat` объекта модуля.
- Существующая СКЗ-реализация принимает AI/DO XLSX, а основное рабочее пространство позволяет вводить DI-модули вручную. Для новой DI-функции владелец выбрал Excel-перекладку.

## Первая итерация: ядро до получения Excel

1. Восстановлена нативная цепь DI: физика в ST → D32V.iNN → программный D32V → DDR_v1.C1. Подробности, направления, резервы, контекст и SHA256 эталонов — в [семантике DI850](../09-di850-native-semantics.md).
2. В `internal/generator/skz.go` добавлен тип DI32/D32V, 32 канала на модуль. FBD сохраняет разреженность и существующие резервные DDR. Дополнительный пустой модуль не создаёт вымышленных получателей. ST850 Measurement/Quality назначает все 32 входа и один Stat, независимо от разреженности FBD. Legacy DI ST и DI ST715 отклоняются до подтверждения профиля.
3. Проверяются повторные получатели в одном ПЛК, поля C1, числовые физические ID, независимые пространства имён ПЛК, пределы транспортных ID и 4096 развёрнутых каналов. Native parity сопоставляет 225 маршрутов, 234 блока/карточки и дословно 297 ST-присваиваний с эталонами.
4. AO850 в целевой ПАЗ запрещён в выделенных FBD/ST генераторах, физическом библиотечном режиме и интерфейсе. Сообщение объясняет отсутствие AO в системе, а не ожидание XML. Профиль715 и отдельная HMI-диагностика715 сохраняются. Принято [ADR-0005](../decisions/ADR-0005-paz850-no-ao.md).
5. При чтении книг применён навык работы с таблицами: без изменения, пересчёта или экспорта. Проверены названия листов четырёх книг `output/`, заголовки и первые строки `AI.xlsx`, `AO.xlsx`, `PS_IO_LIST_SCS_v4_new.xlsx`. Большой импорт через Artifact Tool остановлен из-за длительности; ограниченная проверка выполнена через read-only ZIP/XML. В `PS_IO_LIST_SCS_v4_new.xlsx` есть 619 DI-строк, но столбцы BL:BP (`D32_Вых`…`D32_Вх`) у них пусты. Это исходный список, не подтверждённая DI-перекладка с назначениями DDR.C1. Правила преобразования этого списка не выдумываются. Загрузчик `/api/skz/*` и UI пока принимают AI/DO, не DI.

### Итог реализации

- Книга прочитана через Artifact Tool в режиме read-only. Лист `PS_IO_LIST_SCS_v4`, диапазон A1:BW1778; 619 DI-строк. SHA256 источника и неизменённой fixture `internal/skzmap/testdata/di.xlsx`: `C9C10D1E86936AC5B5BE17B76E2BDEFEDF71F97321938D1373CA179884879339`.
- Нативный A11 сопоставлен с исходными позициями: 225 маршрутов, из них 213 имеют совпадающие имена, 12 содержат LZS в книге и LZSA в XML. По ответу владельца приоритет имеет Tag No. Строка1578 SPARE соответствует пустому каналу19 A11-13; она не превращается в `_SPARE` и не уплотняет нумерацию.
- По подтверждённому правилу Main_module → C1, Redundant_module → C2 одного DDR. Наличие C2 проверено в библиотеке DDR; нативный FBD подтверждает только C1. В XML оба поля ссылаются на одну карточку владельца, повторное назначение одного поля отвергается.
- `internal/skzmap/raw_di.go` читает исходные поля без готовых D32/ST-формул. Другие типы I/O пропускаются с предупреждением; подготовленные AI/DO сохраняют прежний входной формат. SCS определяет ПЛК независимо от удалённого шкафа. Пустой DI-модуль сохраняется; реальные резервные DDR не удаляются. Неподдержанные типы DI, дополнительные Main_module2/Redundant_module2, конфликты размещений/получателей и повреждённые заголовки отклоняются явно.
- UI раздела СКЗ/ПАЗ и `/api/skz/preview`, `/api/skz/generate` принимают книгу. Доступны выбор групп, число дополнительных модулей и физический ID каждого модуля. ST требует CPU850 Measurement/Quality, программный FBD допускает оба CPU. Ограничения DI не блокируют выбранные AI/DO при снятом выборе DI.
- Контекст DI из эталона: ControllerID189312, ResourceID644, GroupID19814, первый POUNum23 в ST и25 в FBD. Ручные значения сохраняются. Для B01 с четырьмя POU диапазоны23…26 и25…28 пересекаются: UI и документация требуют вручную выбрать свободные непересекающиеся диапазоны при совместном импорте.
- Контрольный состав всей книги: 3 ПЛК, 8 POU, 50 модулей, 1236 связанных позиций (618 C1 +618 C2). При выборе всех групп один режим создаёт 3 XML. FBD: 1286 блоков, 1236 связей, 668 карточек. ST: 1650 присваиваний (32 входа + Stat на каждый модуль). Физические ID в пользовательские выходы не угадывались; проверочные документы создавались только в временных каталогах тестов.
