- Статус: Выполнена; импорт и исполнение в SCADA ожидают проверки
- Дата: 28.09.2026
- Источник: запрос владельца, `XML dev/DO_FBD_example.xml` и `DO генерация (1).xlsx` в родительском рабочем каталоге.

- Связано: [TASK-0007](TASK-0007-raw-do-excel.md), [TASK-0009](TASK-0009-do-st-full-channels.md).

## Запрос и ожидаемый результат

Обновить генератор DO FBD по предоставленному правильному экспорту и Excel-карте. Сохранить раздельные ПЛК, существующие DI/AI и полные 32 присваивания DO ST через D32V.

## Известный контекст и доказательства

- Excel изучается только для чтения. Лист1: заголовок в строке 1, 408 назначений B03. Лист2: заголовок в строке 2, 1284 назначения B01. Шаблоны: `простой`, `DO-1`.
- Новая подготовленная карта использует правую часть `SCS DO`: встречаются `_XYC` от Loop, отличные от `Марка`. Это отдельный формат от исходной PS_IO_LIST, для которой остаётся Tag No + `_DDVH`.
- Нативный XML содержит DO_A70, CPU850, 12 модулей, 382 назначения, 191 уникальную BOOL-переменную, промежуточные NOT и цепи физическое Quality → QUAL_STAT → sts. Итог: 800 блоков, 788 связей, 215 карточек.
- Пользователь ранее подтвердил все 32 канала DO ST через D32V. Отсутствующие теги не придумываются.

## Пробелы контекста и вопросы

| ID | Требуемая информация | Подзадача | Ответ / статус |
|---|---|---|---|
| Q-TASK-0010-01 | NOT только для DO-1 или для всех DO? XML показывает только DO-1 | Инверсия технологического сигнала | Владелец: «Все DO через NOT», затем «not в данном случая является инверсной логикой ПАЗ». Принято для нового режима DO ПАЗ, обычный software остаётся без инверсии |
| Q-TASK-0010-02 | Импорт результата в целевую SCADA: версия, файл, наблюдение | Подтверждение совместимости | Требуется после структурных тестов |
| Q-TASK-0010-03 | Источник физической диагностики | Адрес Quality | Владелец: «Диагностика берет сигнал 0 канала физического модуля». Явный ModuleID и канал 0, без вывода ID из слота или первого занятого канала |
| Q-TASK-0010-04 | Префикс D32V: удалённый шкаф XML или имя SCS Excel | Согласование имён FBD/ST | Владелец: «Всегда использовать имя ПЛК». Имя `_<SCS>_<Module>`, переименование ПЛК по шкафу запрещено |

## Решение и план проверки

1. Сопоставить XLSX, блоки, карточки и связи XML; не выводить правила для отсутствующего шаблона без подтверждения.
2. Добавить подготовленный DO-формат, точные нативные блоки/связи и управление необходимыми физическими ID.
3. Проверить входную книгу, регрессии DI/AI/DO, API/UI, генерацию по ПЛК и счётчики ID.
4. Обновить семантику, README, собрать EXE. Импорт и исполнение SCADA отдельно от проверки XML.

## Выполненная работа

Парсер подготовленного DO исправлен: имя из правой части SCS DO, смешанные метаданные строк внутри модуля, поканальный Template. AI и исходный raw IO сохраняют свои правила. Бинарные источники сохранены как неизменённые тестовые образцы, SHA256 сверены с исходниками.

Реализован отдельный профиль `native850` без изменения обычного `software`:

- BOOL → NOT → D32V.iNN для всех DO ПАЗ.
- `_IO_I<ID>_DO32P_0_VAL_DIAG.Quality` → QUAL_STAT → D32V.sts каждого модуля, включая добавленный резервный.
- Все физические ID обязательны, явный 0 допустим, дубли внутри одного ПЛК запрещены.
- Только DO, CPU850, Measurement/Quality. Пропущенные каналы не получают вымышленные BOOL/NOT.
- Имена экземпляров всегда от SCS. Один XML на ПЛК, одна POU на крейт.
- В UI добавлен режим «FBD DO · NOT и диагностика (850)», сохраняющий ручной контекст и ID при переключениях. В API `doFBDProfile`, `nativeDOContext`; файлы `_FBD_PAZ_<ПЛК>.xml`.
- Строгий валидатор проверяет сигнатуры, владельцев карточек, направленные связи и полные цепочки. Параметры страницы сопоставлены с эталоном.
- DO ST остаётся 32 присваиваниями на модуль без дополнительной инверсии. Обычный FBD остаётся прямым.

Файлы: `internal/skzmap/parser.go`, `prepared_do_test.go`; `internal/generator/skz.go`, `skz_native_do.go`, `skz_native_do_test.go`; `internal/appserver/skz.go`, `skz_native_do_test.go`; `web/skz.js`, `skz_test.cjs`, `index.html`.
