- Связанные документы: [TASK-0006](TASK-0006-di850-paz.md), [XML-профили](../04-xml-formats.md#102-do-из-исходного-io-xlsx-с-сохранением-di), [матрица CPU](../08-controller-profiles.md), [ADR-0006](../decisions/ADR-0006-raw-do-source-and-placements.md).

## Запрос и ожидаемый результат

Расширить загрузку исходной книги PS_IO_LIST_SCS для DO, сохранив работающий DI и подготовленные перекладки AI/DO. Не переименовывать DI в DO и не откатывать подтверждённые C1/C2. Один XML на выбранный ПЛК, физические ID задаются пользователем.

## Известный контекст

Книга содержит смешанные I/O Type: 487 DO-строк (DOR-P, DOR-VFC, DOR (SCS3)), 619 DI-строк и другие типы. В DO заданы Main_module, Main_module2, Redundant_module, Redundant_module2 и Channel. Все 487 DO-строк содержат четыре разных размещения; всего 1948 физических назначений в 72 модулях, 12 группах, 3 ПЛК; конфликтов позиций нет. В 250 DO-строках Loop отличается от Tag No; явных DO SPARE/пустых Tag No нет. D32-столбцы не заполнены. SHA256 источника: `C9C10D1E86936AC5B5BE17B76E2BDEFEDF71F97321938D1373CA179884879339`, соответствует неизменённой fixture из TASK-0006. Чтение выполнено через навык таблиц и Artifact Tool, без редактирования книги.

## Решение и план проверки

1. Преобразовать Tag No (`-` → `_`, ведущий `_`) и добавить `_DDVH`; не использовать Loop вместо него.
2. Развернуть каждую DO-строку в указанные физические размещения. Повтор логического источника на разных выходах допустим; конфликт одной позиции отвергается. SCS определяет ПЛК, исходные номера каналов сохраняются.
3. Расширить parser/UI/API для смешанного DI/DO. Сохранить DI C1/C2 и SPARE, подготовленные AI/DO, ограничения физических профилей. Проверять пересечения добавляемых модулей с обоими типами даже при снятом выборе другой группы.
4. Проверить выбор только DO, только DI и их совместную генерацию, направления FBD/ST, независимость ПЛК, повторы, ID и ошибки без записи результатов. Запустить Go/JS-тесты, vet, сборку; записать результаты.

## Выполнено

1. Общий парсер исходной IO-книги обрабатывает DI и DO. Для DO поддержаны `DOR-P`, `DOR-VFC`, `DOR (SCS3)`, обязательный Main и до трёх дополнительных явных размещений. Имя нормализуется из Tag No с добавлением `_DDVH`. Пустые необязательные размещения пропускаются, пропущенные каналы не уплотняются. Пустой DO Tag No и SPARE/Reserve/Резерв без имени отвергаются с объяснением, а не превращаются в вымышленные переменные.
2. Повтор источника на разных выходах сохраняется в FBD и ST. Идентичное назначение той же физической позиции в повторной строке объединяется с предупреждением; конфликт источников и повтор модуля в разных полях одной строки отклоняются. Разные направления не могут занять один физический модуль. SCS задаёт независимое пространство каждого ПЛК.
3. Сохранены DI Main/Redundant → C1/C2, пропуск DI SPARE, имена LZS и обработка подготовленных AI/DO-карт. Автоматический суффикс применяется только к raw DO, не к буквальным тегам подготовленных выражений.
4. В UI добавлены «Только DO» и «Только DI». Начальные параметры определяются выбранным направлением, ручные значения и ModuleID сохраняются. При смешанном выборе видна подсказка об общем контексте. DI ST850-ограничение не блокирует выбор только DO на CPU715. Дополнительные модули проверяются также против невыбранных групп другого направления.
5. Независимое ревью обнаружило ошибку FBD при повторении одного BOOL-тега с разным регистром на разных выходах. Воспроизведена падающим тестом, исправлена канонизация `Block.Info` по общей карточке; регрессионный тест проверяет ссылки внутри и между POU.
6. Обновлены README, описания API/форматов/профилей, семантика DI и ADR-0006. Существующие незакоммиченные изменения сохранены. Пользовательские Excel, XML-эталоны, `output/`, `data/state.json` и конфигурация не изменялись; результаты тестовой генерации создавались только во временных каталогах.
