- Дата: 25.09.2026.
- Статус: **Выполнена**.

Создать в проекте понятную и подробную документацию для человека и следующих программных сессий: цель, текущее устройство, целевая архитектура, схемы каждого семейства XML, реестр обязательных уточнений и процесс дальнейшей работы через документы.

## Источники и границы

Изучены текущие исходники Go/JS, README, семантика шаблонов и IO-диагностики, существующие тесты и сохранённые уточнения владельца. PostgreSQL, orchestrator и удалённый сервер не предоставлены; их существование в текущем приложении не заявляется. Код, EXE, конфигурация, ID-состояние и пользовательские результаты этой задачей не изменяются.

## Результат и продолжение

Основной вход: [docs/README.md](../README.md). Визуальные схемы: [overview.html](../overview.html). Формализованные вопросы: [06-open-questions.md](../06-open-questions.md).

Объём пакета: 18 Markdown-документов в `docs/`, 34 Mermaid-схемы, отдельный офлайн HTML с девятью деревьями XML и деревом XLS. Дополнительно созданы корневые правила AGENTS.md и ссылка из README приложения. Алгоритмы и EXE не изменялись; пересборка и импорт в SCADA для этой документационной задачи не требовались.

Следующее содержательное действие: внести сведения о ролях orchestrator/server, требуемых профилях и схеме БД, затем поставить отдельную интеграционную задачу с достаточным контекстом. Это не разрешение придумывать отсутствующую схему или начать её реализацию.
