# Глоссарий и идентичность сущностей

Термин без уточнения профиля может иметь разный смысл. В документах и вопросах следует использовать точное имя сущности.

| Термин | Смысл в проекте | Не путать с |
|---|---|---|
| SCADA | Закрытая целевая инженерная/операторская система; внешний обмен только через экспорт/импорт XML, [ADR-0003](decisions/ADR-0003-scada-xml-boundary.md) | Локальный веб-интерфейс генератора и API собственной цепочки |
| XML-экспорт SCADA | Файловый снимок экспортируемой части проекта, источник доступного контекста и примеров | Полный доступ к внутреннему состоянию SCADA или доказательство исполнения логики |
| ПЛК / Controller | Целевой контроллер и его конфигурация | Транспортный ControllerID сам по себе |
| FCS / SCS | Поля имени/принадлежности контроллера в разных входных картах | Универсальный первичный ключ PostgreSQL — пока не определён |
| POU | Программная организационная единица; в XML `OnePOU` | Физический модуль, который может делить POU с другими |
| FBD | Графические вызовы, переменные, константы и связи внутри POU | HMI-мнемосимволы и диагностические кадры |
| ST | Текст программы в `STCODE`; текущие специализированные режимы создают перекладки | Все возможные алгоритмы управления технологией |
| HMI / операторский интерфейс | Кадры, графические примитивы, представления, навигация, команды | FBD-графика программы ПЛК |
| Модуль | Физическая или добавленная инженерная единица I/O | POU с похожим именем |
| Обозначение модуля | Например A1-15; для имён объектов используется A1_15 | Реальный числовой ModuleID |
| Канал | Нумерованная позиция конкретного модуля | Уникальный логический сигнал: он может иметь несколько назначений |
| Тег | Имя экземпляра/логической переменной | Тип объекта или его числовой ISA ID |
| ObjectType | Тип SCADA, например AD3_v2, AN_v1, D32V | Template и библиотечное представление |
| Template | Шаблон/профиль импортируемого объекта или графики | OBJTYPE: в XLS для AN_v1 шаблон — AN |
| Card / карточка | Запись экземпляра или ссылка на объект, определяемая конкретным XML-профилем | Сам физический вход/выход |
| Владелец поля | Блок объекта, которому принадлежат `.Out`, `.Stat` и другие поля | Независимая переменная с похожим именем |
| Свободный резерв | Незанятая позиция, которой профиль может назначить резервный объект/поле | Рабочий резервированный сигнал с суффиксом `_reserve` |
| Группа СКЗ | ПЛК + направление + префикс модуля, например AI_A1 | Число итоговых POU: AI FBD разбивает группу по модулям |
| Снимок | Зафиксированная версия входа и параметров | Текущая форма, которая может быть изменена после генерации |
| Артефакт | Конкретный сформированный XML/XLS | Живое представление текущих настроек |
| Orchestrator | Компонент целевой цепочки; точная роль открыта в Q-INT-001 | Не подразумевается конкретный сервис или LLM |
| Server | Компонент между orchestrator и БД; роль открыта в Q-INT-002 | Не автоматически локальный HTTP-сервер EXE |
| PostgreSQL | СУБД в указанной владельцем цепочке получения инженерных данных | Внутреннюю БД закрытой SCADA; текущее локальное `data/state.json` |
| ADR | Запись принятого архитектурного/общепроектного решения | Предложение без решения владельца |

## Разные идентификаторы

| Идентификатор | Где используется | Источник / область |
|---|---|---|
| ModuleID | Адрес в ST, например `_IO_I15_AI16H_0_VAL` | Реальная конфигурация ПЛК; для СКЗ вводится человеком |
| OnePOU.ID | Транспортная идентичность POU внутри XML | Локальный NextPOU или параметры соответствующего режима |
| POUNum | Номер программной POU в контексте импорта | Выбранное начало + последовательность; не то же, что OnePOU.ID |
| GroupID | Группа POU/контекст размещения | Целевой SCADA-проект/профиль |
| T11ID | Примитивы и связанные транспортные сущности | Выделенный диапазон генератора |
| cardId / CardID | Ссылка блока/мнемосимвола на карточку | Таблица карточек соответствующего XML |
| ISA type ID / IsaObjId | Числовой идентификатор типа | Библиотека/профиль; не ID экземпляра |
| ObjMSID | Идентификатор представления/мнемосимвола в HMI | Внешняя библиотека и таблицы зависимостей |
| Page ID | Страница оператора и переходы на неё | NextPage и таблицы HMI; не NextPOU |
| ControllerID | Контекст экспорта POU | Профиль проекта; не обозначение модуля |
| `ResuorceID` | Точное историческое имя XML-атрибута ресурса | В коде API обычно `resourceId`; опечатка в XML сохраняется |
| `resourceNumber` | Ресурс в символьной ссылке HMI/XLS | Отдельное пользовательское поле; не `ResuorceID` |
| DB primary key | Будущий ключ сущности PostgreSQL | Пока неизвестен; нельзя подставлять его в любое поле XML ID |

## Пример одного состава в разных представлениях

При 16 модулях A1 по 16 AI-каналов СКЗ:

- AI FBD: 16 POU `AI_A1_00`…`AI_A1_15`, по одному модулю на POU.
- AI ST: одна `AI_A1_channels`, 256 каналов, 512 присваиваний Xin/Xs.
- Каждый дополнительный AI-модуль создаёт 16 резервных экземпляров по принятому правилу.
- HMI CPU850 по этому входу не следует считать автоматически поддержанным: требуется свой профиль.

Это пример полного набора каналов, а не правило дополнять разреженный исходный модуль. Если в исходном модуле СКЗ указаны только четыре канала, они сохраняются как четыре; новые вручную добавленные модули заполняются полностью.
