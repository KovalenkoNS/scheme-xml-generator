# Диагностика ПЛК: IO → операторский интерфейс

Профиль составлен по `Full_IO.xlsx`, производным `AI.xlsx` / `AO.xlsx` и нативному `3000_D_SC_B01.xml`. Исходники читаются без изменений; при запуске достаточно IO, остальные образцы преобразованы во встроенные ресурсы.

## Источники и приоритеты

| Источник | Что определяет |
|---|---|
| IO: Control cabinet + Main/Redundand module | Физический шкаф, крейт, слот, резервирующее размещение |
| IO: FCS | Владелец крейта; противоречивые строки исправляются по строгому большинству внутри шкафа/крейта с предупреждением |
| IO: ModuleType + Channel | Тип и ёмкость, точная позиция без сдвига пропусков |
| IO: Tag No, Loop, Loop No, TYPNO, LL/L/H/HH | Наличие сигнала и входы правила имени |
| Явные SCADA Tag / SCADA Reserve Tag | Приоритетное пользовательское имя без эвристики |
| Проверенная перекладка AI/AO | Точные существующие имена при совпадении отпечатка исходной строки |
| Нативный XML | Схема вложенности, лексика, геометрия, типы мнемосимволов, рецепторы, картинки |

Отпечаток калибровки содержит исходный FCS, шкаф, тип, основной/резервный модуль, канал, Loop, Loop No, Tag No, TYPNO, четыре аварийных порога и роль размещения. Номер строки не входит: перестановка строк не меняет привязку. Любое изменение содержательных полей отключает устаревшую калибровку. 2531 запись профиля — не таблица статического оборудования: новые модули всегда определяются IO.

В `AI.xlsx` две ST-строки (`Xin/ValueDINT` и `Xs/Status`) соответствуют одному каналу и одному диагностическому объекту, а не двум сигналам. Основное и резервное AI-размещения различаются суффиксами `_main` / `_reserve`. В AO оба размещения ссылаются на один `AN_v1`; правило удаления повторного FBD-вызова в диагностике не применяется.

Резервные каналы не наследуют имя другого модуля: `_FCS_A11_14_5`, а не скопированное `_FCS_A10_14_5`. Такие устаревшие привязки найдены в нативном примере и намеренно не переносятся.

Для новых строк без калибровки AI использует Loop и наличие порогов; регулируемые контуры — Loop No с измерительным суффиксом I. AO использует Tag No и подтверждённые преобразования TY→TV, PY→PV, FY→FV, LY→LV, HY→HIC, XI→XIC, ESI→ES, WI→WV; SY сохраняется. Нераспознаваемые случаи отклоняются с требованием явного SCADA Tag. Вычисленные аналоговые имена отмечены в предпросмотре для проверки, поскольку инженерное переименование невозможно гарантированно вывести из схемы подключения.

## Иерархия и внутренние ссылки

```text
BufScada / Pages / OnePage: <ПЛК>
└─ SUBPAGES
   ├─ OnePage: Шкаф РСУ <ПЛК>. Задняя панель
   │  └─ SUBPAGES / OnePage: AI_… и AO_… соответствующих модулей
   └─ OnePage: Шкаф РСУ <ПЛК>. Передняя панель
      └─ SUBPAGES / OnePage: AI_… и AO_… соответствующих модулей
```

Каждый модуль занимает собственный слот `X=95+63*slot`, крейты размещаются с шагом 440 по Y. Три исходных изображения сохраняют вид пустых слотов и стоек. CPU715 занимает 00/01 первого крейта; коллизия с IO-модулем отклоняется. DI/DO показаны на шкафной панели без выдуманных дочерних кадров — так устроен образец.

| Связь | Представление |
|---|---|
| Примитив модуля → экземпляр | CardID → CARDSINFO, `2/<ПЛК>/<ресурс>/<тег>/(тип)` |
| Модуль → дочерний кадр | Вложенный OneReceptor TYPEID=1, PARAM_INT=ID кадра |
| ID кадра → путь | GRPAGESINFO, `Диагностика\<ПЛК>\<панель>\<кадр>` |
| Квитирование → команда | TYPEID=3 → CHARTDATA/OneChart MODE=12 → PARAMID из CARDPARAMSINFO |
| Команда → родительский рецептор | OneChart.PID = OneReceptor.FROMID |
| Примитив → представление | ObjMSID → PAGEMSINFO.Info |
| Рамка крейта → растровое изображение | PicId → PICS |

Для AI/AO команда — `([]КОМ. КВИТИРОВАТЬ)`, для DI/DO — `([]D32_КОМ. КВИТИРОВАТЬ)`. CPU не включается в этот список. На каждой панели кнопка перечисляет только её реальные модули; все модули выбранного ПЛК охвачены.

Имена дочерних кадров: `AI_<часть ПЛК после _SC_>_<модуль>_AI16H` и `AO_<часть ПЛК после _SC_>_<модуль>_AOC4H`. Суффиксы B07_1/B07_2 сохраняются. Переключение панелей направлено на новые ID, а не на ID исходного B01.

## Внешние зависимости и транспорт

Выгрузка не включает определения библиотеки и служебного шаблона. Сохраняются именованные ссылки `4705 → Диагностика`, `6580 → Служебные шаблоны\Шаблон диагностики контроллеров_PS`. Правую навигацию других ПЛК обеспечивает существующий шаблон целевого проекта, а не копия данных B01. Переименование существующих внешних страниц требует согласованного изменения проекта SCADA.

Все документные ID создаются заново: страницы из NextPage; примитивы, рецепторы, команды и параметры квитирования — из общего безопасного диапазона NextT11; карты — из NextCard. NextPOU не расходуется. Внешние библиотечные ID сопровождаются их именованными таблицами. Проверяются уникальность, разрешимость и принадлежность ссылок после сериализации.

Генератор сохраняет нативный компактный XML-диалект, самозакрывающиеся пустые значения и CRLF. Ошибочные CP1251-байты имени слоя в UTF-8-образце нормализованы при подготовке встроенного ресурса. Исходный файл не исправлялся на диске.

## Контрольный набор и границы

Full_IO: 3448 строк оборудования, 90 строк без назначения; после согласования владельцев — 8 ПЛК, 380 модулей (167 AI, 153 AO, 35 DI, 25 DO), 5204 позиции, 344 кадра. 16 строк с ошибочным FCS исправляются только в памяти по шкафу/крейту.

B01: 52 модуля, 672 позиции, 50 страниц, 644 примитива. Страницы и графика совпадают по объёму с нативной группой; карточки пересозданы по актуальным данным. Это не доказывает импортную совместимость новой версии: окончательная проверка выполняется импортом в тестовый проект SCADA.

Профиль геометрии — TENIX-CPU715, 16 слотов крейта, две панели. Это не универсальный конструктор произвольного оборудования. Неизвестные типы модулей, неоднозначное владение крейтом, повторно занятый канал, отсутствующий кэш формулы или повреждённый XLSX отклоняются вместо частичного молчаливого экспорта.

Калибровку при обновлении эталонных IO/AI/AO можно явно пересобрать: `SCHEMEGEN_REBUILD_IO_PROFILE=1 go test ./internal/iomap -run TestRebuildReferenceProfile -count=1` (в PowerShell переменную задают через `$env:SCHEMEGEN_REBUILD_IO_PROFILE='1'`). Обычные тесты и запуск приложения профиль не перезаписывают.
