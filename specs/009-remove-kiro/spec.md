# Очистка прежнего процесса и явный запуск reviewer

Status: implemented
Date: 2026-09-30

Источник: владелец 30.09.2026 явно разрешил удалить архив Kiro и устаревшие Markdown, сохранить актуальные SDD-документы, распространить очистку на четыре репозитория, создать коммиты и отправить их в существующие origin. Отдельным последующим указанием reviewer выключен: запускать его только по явной просьбе пользователя. Это заменяет прежнее обязательство запускать независимого проверяющего перед каждым итогом и разрешает удаление доказанно заменённых материалов процесса. Связанный пакет оркестратора: [Host-client 013](../../../../Develop/Host-client/specs/013-remove-kiro/spec.md).

## Пользовательские истории

US1: разработчик получает один действующий процесс GitHub Spec Kit без устаревших инструкций создания TASK и зависимостей Kiro.

US2: пользователь управляет запуском reviewer; завершение документальной работы само по себе не запускает приложения или независимую продуктовую приёмку.

## Требования

- **FR-001**: удалить доказанно заменённый `docs/templates/task.md`, исправить входящие ссылки и убрать упоминания отсутствующей интеграции Kiro из действующих инструкций. Предметные TASK/ADR, вопросы, семантика XML и все числовые SDD-пакеты сохраняются.
- **FR-002**: действующие инструкции, конституция, шаблон приёмки и пакет 008 запускают reviewer только по явной просьбе пользователя. Отсутствие незапрошенного reviewer не является отказом; реальные FAIL и NOT-RUN продуктовой приёмки сохраняются.
- **FR-003**: до изменения сохранить точные копии затрагиваемых файлов и исходных незакоммиченных правок вне репозитория; проверить структуру SDD, ссылки и смысл изменений без runtime-сценариев и без reviewer.

## Приёмка

SC-001: устаревший шаблон отсутствует; ссылки действующих документов ведут к Spec Kit и существующим приложениям контекста/импорта.

SC-002: ни одна действующая инструкция не требует автоматического запуска reviewer; исторические результаты не объявляются новой проверкой.

SC-003: адресные проверки документов имеют фактические результаты, исходные пользовательские изменения сохранены, runtime генератора и пользовательские данные не изменены.

## Границы

В XML Generator нет файлов, скриптов, hook или зависимостей Kiro. Историческая запись в verification пакета 001 о том, что такой каталог не создавался, остаётся фактом прошлого. Сохранение TASK-0001…0010 и предметных семантик обосновано их уникальными решениями, открытыми вопросами и входящими ссылками. Продуктовая приёмка пакета 008 этой очисткой не закрывается. Commit/push выполняет координатор после согласования точного состава изменений.
