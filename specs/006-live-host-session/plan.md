# План

Применимые правила: SDD-001/003/004, CODE-001/001-T/002/003, ARCH-001, DATA-001, INT-001, UI-001, XML-001/005.

1. Удалить жёсткий `contract-pending` workspace. Backend `internal/integration/hostclient` обнаруживает только loopback URL из окружения, читает `/api/device`; не знает XML или DOM. `internal/httpapi/host` возвращает текущий снимок и короткие статусы. `appserver` только соединяет компоненты.
2. Использовать фактическое состояние текущего Host: connected/reachable/authenticated, server, username, checked_at. Не дублировать серверную авторизацию или передавать токен. Отдельного сессионного кэша в генераторе нет.
3. `web/host` владеет состоянием запроса, циклом обновления и компактным отображением соединения. Один активный цикл, отмена предыдущего запроса и счётчик запросов защищают от гонок. Shell только подключает компонент.
4. Ранее выполненные Go/Node/browser сценарии с синтетическим Host сохранить как технические результаты, без объявления интеграционной приёмкой. По уточнению владельца 30.09 проверить соединение исключительно по действующей цепочке запущенный Generator → полное запущенное окно Host-client → действующий Host-server → PostgreSQL. Зафиксировать фактическое подключение Server к БД и изменения login/logout/address/network в одном экземпляре Generator; прямое обращение модуля к Server/БД и подмены компонентов запрещены. Стандартный Generator устанавливается Host из GitHub. Полные проверки кода и фактическая приёмка цепочки записываются раздельно; каждый exit/result фиксируется.

Уточнение владельца сужает обновление до состояния соединения. Просмотр таблиц и инженерный mapping JSON-колонок в AI/AO/DI/DO не входят в задачу; информация о пока недоступном IO-контракте показывается отдельно от соединения.
