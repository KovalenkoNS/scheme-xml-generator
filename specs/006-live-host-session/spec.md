# Живое подключение к Host

Status: verified
Created: 2026-09-30

Источник — критическое замечание владельца и явное уточнение: «генератор не видит соединения и не обновляет его». Обновлению подлежит соединение, не таблицы и не версии приложений. Связанный пакет Host-client: [011](https://github.com/KovalenkoNS/Host-client/tree/main/specs/011-live-workspace).

## User Stories

### US1 — Подключение без отдельного входа

Запущенный Host генератор показывает текущие адрес, пользователя и состояние серверной сессии; вход, выход, смена адреса и потеря сети отражаются без перезапуска.

### US2 — Достоверное состояние

Открытый генератор отражает потерю Host/Server, выход и восстановление соединения. Старое успешное состояние не остаётся на экране после ошибки обновления.

## Functional Requirements

- **FR-001**: Generator использует только переданный Host адрес `HOST_CLIENT_API_URL` локального API. Прямые запросы к Server/PostgreSQL, получение токенов и отдельный вход в модуле отсутствуют. Самостоятельный запуск явно показывает отсутствие Host и сохраняет локальную страницу.
- **FR-002**: Состояние Host/Server обновляется при открытии, каждые 3 секунды, после возврата фокуса и вручную. Доступность Host, настройка Server, серверная авторизация и доступность данных — разные состояния с короткими сообщениями.
- **FR-003**: Основная страница показывает фактические текущий адрес Server, пользователя и статус из `/api/device` Host. Не добавляются просмотр таблиц, новый вход, настройки Server или обновление приложений. Отсутствующий контракт инженерных IO-данных не смешивается с состоянием соединения.
- **FR-004**: Ошибка обновления очищает прежний успешный статус. Поздний ответ отменённого запроса не может затереть более новое состояние; сетевые запросы ограничены временем и размером, browser не кэширует снимок.
- **FR-005**: Транспорт Host, HTTP-адаптер генератора и интерфейс обновления разделены по предметным каталогам; тесты находятся отдельно, функции имеют краткие содержательные комментарии. Проверки компонентов не подменяют приёмку соединения действующей цепочки.

## Acceptance

По прямому уточнению владельца от 30.09.2026 и [INT-001](../../.specify/memory/rules.md) соединение принимается исключительно с полным запущенным окном Host-client, действующим Host-server и подтверждённым подключением к PostgreSQL. Generator установлен через каталог GitHub Host. Прямое обращение модуля к Server/БД и синтетическая подмена любого звена не подтверждают эту приёмку.

1. Установить Generator из GitHub через каталог полного Host и запустить его из Host; вход/выход/смена сервера в Host меняют открытую страницу одного экземпляра Generator без перезапуска. Адрес оркестратора передаёт сам Host.
2. Потеря Host/Server или отказ авторизации убирают прежний статус «Подключено» и не раскрывают технический ответ/секрет; восстановление видно в том же экземпляре.
3. Задержать чтение, затем инициировать новое обновление; поздний ответ не публикуется.
4. Запуск без Host оставляет локальную генерацию рабочей.

## Boundaries

Сопоставление инженерных полей, ключей версий/проектов и поддержанных профилей генерации остаётся открытым в [вопросах интеграции](../../docs/06-open-questions.md). Этот пакет не вводит получение/просмотр таблиц и не объявляет генерацию по БД реализованной. Импорт/исполнение SCADA не входят в изменение.

## Success Criteria

- **SC-001**: При доступном локальном Host обновление наблюдается в следующем цикле 3 секунды плюс время ограниченного HTTP-запроса.
- **SC-002**: На действующей цепочке Generator → Host-client → Host-server → PostgreSQL смена соединения видна без перезапуска; отрицательные сценарии не возвращают устаревший успех. Исторические изолированные HTTP/browser проверки не закрывают этот критерий.
