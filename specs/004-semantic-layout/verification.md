## Проверка смысла и границ

- `domain/hardware` владеет подтверждёнными физическими ёмкостями. Адаптеры AO/IO/assignments, FBD/ST/HMI и технологические объекты читают его; ограничение экспортного AO-ST профиля находится отдельно и не связывает CPU850 с ПАЗ.
- `ProgramContext`, `HMIContext`, `OutputSTDocument`, `ControllerResult` имеют нейтральных владельцев. AO-default находится в отдельном файле; module/HMI не наследуют частный AO Project. Регрессия проверяет независимость их значений.
- Общий ST использует предметные метаданные назначений, не SKZ. FCS/SCS остаются только входными заголовками/совместимыми wire-полями. HTTP aliases /api/skz не задают модель генератора.
- Fixed AO/module-FBD, legacy-планировщик и nil-profile fallback исключены из production. Прямой core-вызов с io.modules отвергается на нормализации, планировании ID и генерации для AI/AO/DI/DO. HTTP410 — отдельный запрет, а не проверка снятого алгоритма.
- Актуальные FBD-тесты подставляют изменённые ISA ID, проверяют обязательность библиотечных метаданных и независимую инверсию BOOL→D32; исходный шаблон не меняется. ST-проверки сохраняют применимые физические ID, полные каналы, снимки и CPU-профили.
- Общие AO fixture helpers находятся только в tests/support. Недостижимые HTTP fixed-assertions, включая ветку после return, исключены из активных Go-тестов и записаны в retired-реестре. Прежнее количество268 тестов не используется как доказательство текущего coverage.
- Контроль комментариев разделён на inventory/comments/boundaries/entrypoint; regression checks не позволяют исключить tests/support или забыть файл/функцию. Указание компонента, входа и эффекта проверялось по телу функций, не по наличию префикса Test.

### История: Смысловой review

SKZ/СКЗ — конкретный прикладной контекст, а не универсальная архитектурная сущность генератора. Исправление не сводится к переносу прежних файлов в каталог `profile`:

- `domain/{assignments,analogoutput,inventory}` содержит ПЛК, модули, каналы и назначения; генераторы больше не импортируют парсеры `aomap/iomap/inputs`.
- `inputs/assignments/{raw,prepared}` интерпретирует разные форматы таблиц. Полнота пары Xin/Xs проверяется только адаптером prepared, по признаку происхождения записи. Общая модель AI не обязана содержать выражения этого формата.
- `generator/moduleprofile` владеет подтверждёнными типами/ёмкостями оборудования и получателями ST; общий планировщик не закрепляет AI16H/DO32P/D32V.
- `planning/legacyfbd` содержит прежние расходы ID и правила группировки фиксированных схем только для исторических регрессий. HTTP-доступ к таким схемам отключён, включая `pous[].io.modules`.
- `controller`, `addressing`, `identifiers`, `modules`, `planning`, `allocation`, `xmlmodel/xmlcodec` имеют отдельные обязанности. Смешанный каталог `profile` удалён.
- Внутренние имена `ControllerName/ControllerCount` обозначают ПЛК. Существующие JSON `fcs/fcsCount/sourceFcs` сохраняются как совместимые имена полей HTTP-контракта; заголовки FCS/SCS и исходные выражения остаются в адаптерах. Веб-предпочтения ModuleID, включая0, сохранены при миграции ключей назначений.

Проверка `TestAbstractionBoundaries` воспроизводит запрещённые зависимости и превращение прикладного имени/столбца в общую модель. Она допускает корректное направление зависимости и совместимые транспортные алиасы. `TestPreparedPairValidationRespectsSourceFormat` проверяет, что правило Xin/Xs не распространяется на другой адаптер.

Краткие комментарии описывают действие, взаимодействующий компонент и данные/эффект. В [support-audit](support-audit.md) отдельно подтверждены63 функции library/XLS/techobjects/config/entrypoint: тела по токенам не изменены. Общий автоматический gate проверяет наличие комментариев и структуру; их смысл проверялся просмотром кода, а не числом строк.

Переименование понятий ПЛК затронуло49 Go-файлов и296 AST-идентификаторов. `.artifacts/controller-names-audit.json` подтверждает сохранность всех строковых литералов и инструкций, без непредусмотренных токеновых изменений. Шесть сценариев `tests/contracts/controller_wire_test.go` сохраняют значения прежних JSON-полей.
