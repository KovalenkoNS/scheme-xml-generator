# План

После отклонения: интерфейс переводится с общего изменяемого window.GeneratorWorkspace/WorkspaceModel на ES-модули с явными импортами владельцев операций. Общие данные состояния остаются в shell/state; модель каждого результата не зависит от DOM. Bootstrap связывает загрузку и события, preview подключается к результату через свой публичный метод. Проверяются реальные исходники, отсутствие ambient namespaces и прежние сценарии браузера; одного изменения script type недостаточно (CODE-001/002/003, FR-002/004/006).

1. Выделить `internal/generator/contracts`, `controller`, `addressing`, `identifiers`, `modules`, `xmlmodel`, `xmlcodec`, `planning`, `allocation` и предметные `fbd`, `st`, `hmi`. Корневой `generator` — фасад, только маршрутизация вызовов и типовые aliases. Единого пакета profile для разных обязанностей нет.
2. Выделить HTTP-предметы независимо от фасада генерации; сборка сервера остаётся через `appserver.New`.
3. Переместить Go-тесты в `tests/whitebox` (отдельный вложенный модуль, чтобы Go не компилировал приватные тесты как самостоятельные пакеты). Драйвер под `tests/` добавляет только тестовые файлы в реальные production-пакеты через Go `-overlay`; дочерний запуск исключает драйвер, использует `-count=1`, учитывает содержимое входов.
4. Веб-файлы и тесты переносит координатор отдельно, сохраняя embedded маршруты.
5. Добавить содержательные комментарии и фактический gate CODE-001/CODE-002; обновить инструкции запуска и выполнить полный набор.
6. Убрать SKZ из общих понятий: `internal/domain/assignments` содержит модель контроллеров/модулей/каналов; `internal/inputs/assignments` адаптирует подготовленные и исходные таблицы. Зависимости направлены от адаптера и генератора к модели. HTTP читает таблицу и передаёт модель планировщику. В браузере используется controllerName; сохранённые пользовательские ModuleID мигрируют на нейтральные ключи без потери значений.
7. После отклонения исправить реальные границы CODE-003: аппаратная ёмкость принадлежит `domain/hardware`, модель ST — `generator/moduleprofile`, ограничения подтверждённого экспорта — `generator/exportprofile`. Нейтральные `ProgramContext/HMIContext/ControllerResult` не принадлежат AO; общий ST не имеет SKZ-метаданных. CPU850 не обозначает область ПАЗ.
8. По согласованному XML-002 удалить фиксированные FBD API/диспетчеры и fallback из production, сохранив только обязательный библиотечный профиль. Неприменимые прежние FBD-утверждения хранить как retired-текст; применимые ST-проверки перенести в предметные внешние тесты. 410-тесты имеют имена проверки запрета и не заменяют retired coverage.
9. Общие тестовые входы имеют одного владельца `tests/support`; CODE-002 gate охватывает все собственные Go-файлы, включая тесты. Смысл комментариев проверяется по телу функции, а не шаблону имени.
10. Фиксировать реальный exit code/ошибки и свежие артефакты каждого прогона по SDD-004. Блокировка записи SOURCE_LAYOUT и последующее восстановление — отдельные факты в [execution-incident](execution-incident.md). Старые EXE/ZIP не подменять молча; новый кандидат проверяется отдельно.
11. Исправить смешение CSS в shell/workspace.css: общая тема и элементы управления имеют нейтрального владельца shared, предметные стили лежат рядом с соответствующим UI-компонентом. Сохранить декларации и фактический каскад, включая media-условия. Сравнить CSS-правила и вычисленные браузером стили до/после, выполнить workspace/preview на новом изолированном кандидате; прежнюю поставку не менять до доказательства.

Предварительное доказательство overlay: Go 1.24 принимает отображение отсутствующего `internal/unit/value_test.go` на файл отдельного тестового каталога; тест получает доступ к приватному символу production-пакета. Минимальный эксперимент сохранён в `.artifacts/overlay-probe-1790681514680`, команда `go test -count=1 -overlay overlay.json ./...` PASS. Версионируемых фиктивных тестовых файлов в production не создаётся.
