# План

1. Независимо прочитать структуру исходной XLSX без её изменения, зафиксировать SHA256, заголовки, количества и неопределённости.
2. Воспроизвести чтение установленным GitHub-модулем через полный Host и действующие Server/БД. Сохранить состояние пользователя; preview не должен генерировать файлы или записывать IO в БД.
3. Исправить предметный адаптер исходного формата и представление результатов, не дублируя существующий алгоритм и не подменяя неизвестные типы/шаблоны догадками. `inputs/assignments/raw/io_list.go` владеет только чтением SCS-колонок в нейтральные IO-записи. Применение подтверждённых SCADA-имён/аппаратных типов принадлежит `generator/moduleprofile`; оркестрация чтения и профиля — `application/ioimport`. HTTP передаёт данные этому сценарию. Не оставлять копию прежнего DI/DO-алгоритма в адаптере.
4. Собрать и доставить модуль через GitHub; проверить исправление только установленным экземпляром. Проверять фактический результат каждой команды и принадлежность артефакта текущей сборке.
5. Обновить контракт источника и документацию. Запустить отдельного subagent для приёмки каждого пункта checklist; незакрытые пункты не переводить в PASS.

Применяются SDD-001…004, CODE-001/001-T/002/003, ARCH-001, DATA-001, INT-001, UI-001, HOST-001, XML-001…006 и все Global/MOD канонического checklist. Исторические изолированные тесты не являются приёмкой этого изменения и не запускаются вместо проверки установленного ПО. Чтение исходников и книги используется для диагностики, а не как доказательство работающего продукта.
