# Чтение фактического IO-листа и приёмка установленного генератора

Status: ready
Date: 2026-09-30

Основание: сообщение владельца30.09.2026 о неверном чтении `XML dev/PS_IO_LIST_SCS_v4_new.xlsx` и обязательной независимой приёмке по `Develop/Host-client/checklist.md`. Пользователь подтвердил замену прежнего требования изоляции: проверять только фактически установленное ПО, сохранять пользовательские данные резервированием и восстановлением.

## Требования

- **FR-001**: исходная книга читается без изменений. Адаптер распознаёт её фактические заголовки, типы IO, ПЛК и все явно заданные размещения; строки не теряются молча. Формат источника не переносится в общую модель оборудования.
- **FR-002**: интерфейс показывает результат чтения DI/DO/AI/AO и точные ограничения/ошибки с листом, строкой и полем. Успех одного адаптера не скрывает потерю данных в другом. Отсутствующие исходные сведения и назначения не выдумываются.
- **FR-003**: исправление доставляется как стандартный модуль из GitHub и проверяется установленным генератором, запущенным полным Host-client при действующем соединении Host → Server → PostgreSQL. Альтернативные окружения и прямой доступ модуля к Server/БД запрещены.
- **FR-004**: перед итоговым ответом отдельный subagent проверяет каждый пункт канонического checklist.md. Незакрытый пункт, FAIL или NOT-RUN означает отказ в приёмке; сборка и исторические тесты его не отменяют.

## Пользовательские сценарии

US1: пользователь выбирает локальный IO-лист, видит реальные ПЛК и направления, может проверить состав прочитанных строк до генерации.

US2: пользователь получает исправление через стандартную поставку Host, а итоговый отчёт содержит независимую приёмку фактически установленного ПО.

SC-001: значения и количества в установленном модуле сопоставлены с неизменённым исходником; расхождения объяснены, потеря строк отсутствует.

SC-002: все пункты checklist имеют доказательства и закрыты независимым проверяющим; иначе работа не объявляется выполненной.

## Неизвестные сведения

Q-IO-008-001 — закрыт: владелец30.09.2026 подтвердил «Для данного случая в системе нет AO». Ожидаемый состав исходной книги:619 DI,487 DO,270 AI,0 AO;138 строк S и263 без типа не имеют физических размещений.

Q-IO-008-002 — закрыт для AI-назначений: владелец указал `XML dev/pack`. AI850 ST подтверждает AI16H, Xin/Measurement и Xs/QUAL_STAT(Quality), 62 реальных имени из Loop + `_main` по A11-00…04. Владелец отдельно подтвердил правило для всей книги: «Да, Main → _main; Redundant → _reserve»; каждый объект получает собственный физический канал. Это основание SCADA-профиля, а не заголовок/аппаратный тип из XLSX. FBD-шаблоны продолжают выбираться из подключённой библиотеки. ModuleID не вычисляется из слота (AI715-образец содержит несовпадающие ID).

Q-IO-008-003 — HMI-граница: `715_DIAG.xml` совпадает с ресурсами существующего профиля715; `850_DIAG.xml` подтверждает отдельный профиль CPU850 с CR1516/CR1508 и MI01. Его наличие снимает запрос повторно предоставить этот образец, но не реализует HMI850 и не задаёт полный аппаратный инвентарь каждой установки. Исправление чтения IO не объявляется поддержкой этого нового HMI-профиля.

Книга — пользовательский исходный материал; в Git не добавляется. Проверка чтения не подтверждает импорт или исполнение XML в SCADA. Основная страница и получение IO из БД не расширяются этим исправлением: речь о локальной таблице.
