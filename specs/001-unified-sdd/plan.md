# Implementation Plan: Единый SDD для XML Scheme Generator

**Branch**: `001-unified-sdd` (идентификатор пакета) | **Date**: 2026-09-28 | **Spec**: [spec.md](spec.md)

## Summary

Применить выбранный владельцем GitHub Spec Kit v1.0.12, сохранив предметную документацию генератора и десять исторических карточек. Общий процесс хранится в `docs/SDD.md`, правила продукта — в `.specify/memory/constitution.md`, постановка этого изменения — только в `spec.md` текущего пакета.

## Technical Context

**Language/Version**: Markdown/PowerShell/Node.js для SDD; Go-приложение не меняется.

**Primary Dependencies**: Официальные шаблоны и инструменты GitHub Spec Kit v1.0.12.

**Storage**: Файлы текущего репозитория; без переноса пользовательских XML/XLSX/состояния.

**Testing**: Общая проверка `node scripts/sdd.cjs check`, проверка ссылок, SHA256 исторических TASK и обзор diff.

**Target Platform**: Windows, VS Code и Codex с локальными skills Spec Kit.

**Project Type**: Независимое локальное приложение генерации XML SCADA.

**Constraints**: Сохранить многочисленные изменения, существовавшие до этой работы; не собирать EXE и не менять пользовательские артефакты.

## Constitution Check

| Принцип | Как соблюдается |
|---|---|
| Независимый продукт | Роли приняты отдельно от неизвестных протоколов и фактической реализации интеграции |
| Спецификация до изменения | Настоящий пакет — единственная постановка миграции |
| Сохранение истории | TASK-0001…0010 и ADR-0001…0008 остаются на прежних путях; новый ADR уточняет процесс |
| Разделение факта и неизвестного | Частичные ответы Q-INT/Q-CTX не закрывают неизвестные детали |
| Доказательства | Проверки и ограничения записываются в `verification.md` |
| Сохранность данных | Код, runtime-файлы, исходные библиотеки и EXE не изменяются этой задачей |

## Design and Migration

1. Добавить официальную основу Spec Kit, общий процесс, локальную конституцию и пакет текущего изменения. Инициализация не должна создавать Git-коммит или переключать ветку.
2. Обновить `AGENTS.md`, `docs/README.md`, главу 07, журналы задач и шаблонов. На этапе перехода старый шаблон карточки сохранялся с предупреждением; по последующему решению владельца от 30.09.2026 он удалён как заменённый ([009](../009-remove-kiro/spec.md)). Пакеты контекста и протоколы импорта остаются приложениями к новым спецификациям.
3. Добавить ADR-0009, заменяющий только прежнее расположение новых постановок из ADR-0001. Предметные ADR не менять.
4. В главах 01/03/06 и визуальном обзоре зафиксировать роли проектов. Q-INT-001/002/003 и Q-CTX-001/002 ответить частично с источником, не приписывая системе неизвестные возможности.
5. Проверить общий процесс, ссылки, неизменность истории и отсутствие затрагивания кода/данных. Связать результаты с FR в `verification.md`.

## Verification Strategy

Для FR-001/002 используется общая проверка SDD; для FR-003 — хеши десяти карточек и отсутствие активного требования создавать TASK-0011; для FR-004 — сопоставление роли каждого проекта в входных документах и вопросах; для FR-005 — сравнение изменений с исходным состоянием и сохранность ограничений SCADA. Проверка Go, импорт SCADA и пересборка EXE не требуются для изменения только процесса и документации, поэтому не выдаются за выполненные.

## Risks and Dependencies

Общие файлы процесса создаются скоординированно для всех проектов, после чего выполняется финальная проверка ссылок. До неё `verification.md` честно содержит `NOT-RUN`. Сохраняется переносимость самого пакета; межпроектные контракты получат собственные спецификации, если появится соответствующая задача. Формат выбран владельцем, дополнительных решений для этой миграции не требуется.
