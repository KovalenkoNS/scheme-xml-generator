# Feature Specification: Единый SDD для XML Scheme Generator

**Feature Branch**: `001-unified-sdd` (идентификатор пакета; ветка этой работой не создавалась)

**Created**: 2026-09-28

**Status**: verified

**Input**: Владелец потребовал единый SDD для отдельных проектов XML sandbox и Develop и выбрал GitHub Spec Kit в VS Code. Host-client — оркестратор; Host-server — авторизация клиентов и маршрутизация; xml-generator — независимое ПО генерации XML SCADA.

## User Scenarios & Testing

### User Story 1 — Единый способ продолжать работу (Priority: P1)

Как разработчик генератора, я хочу находить постановку, проектное решение, работы и результаты проверки в одном пакете общего формата, чтобы продолжать работу без восстановления чата и без конфликтующих копий требований.

**Why this priority**: Проекты остаются самостоятельными, но общий способ работы устраняет несовместимые процессы и сохраняет накопленный контекст.

**Independent Test**: Пройти от `AGENTS.md` через `docs/SDD.md` к текущему пакету, проверить четыре файла, трассировку требований и доступность исходных TASK.

**Acceptance Scenarios**:

1. **Given** новый запрос генератора, **When** создаётся спецификация, **Then** используется единственный пакет `specs/<NNN-slug>/` с `spec.md`, `plan.md`, `tasks.md`, `verification.md`.
2. **Given** прежняя карточка TASK с открытым ограничением, **When** начинается продолжение, **Then** новый пакет ссылается на неё, исходная карточка и её доказательства сохраняются.
3. **Given** изменение контракта с Host-client или Host-server, **When** описывается область работ, **Then** роли и отдельные локальные пакеты соответствуют владельцам; факт интеграции не заявляется без проверки.
4. **Given** выполненные работы с непроведённой проверкой, **When** читается `verification.md`, **Then** результат этой проверки обозначен `NOT-RUN`, а не успешным.

### Edge Cases

- Историческая задача выполнена структурно, но импорт SCADA ожидается: миграция не закрывает это ограничение.
- В рабочем дереве есть чужие незакоммиченные изменения: процесс добавляется без отката или перезаписи кода и артефактов.
- Роль компонента задана, но протокол неизвестен: вопрос закрывается только в известной части.
- Генератор используется отдельно от остальных проектов: его локальная конституция и пакет остаются достаточной точкой входа.

## Requirements

### Functional Requirements

- **FR-001**: Новые изменения MUST использовать GitHub Spec Kit v1.0.12, локальную конституцию и один пакет `specs/<NNN-slug>/{spec,plan,tasks,verification}.md`; общие шаблоны и инструменты доступны в проекте.
- **FR-002**: Пакет MUST связывать истории `US*`, требования `FR-*`, критерии `SC-*`, задачи `T*` и фактические проверки; результаты проверок обозначаются `PASS`, `FAIL` или `NOT-RUN` с доказательством.
- **FR-003**: Исторические TASK-0001…0010 MUST сохранить имена и содержимое; действующие указатели MUST направлять новые изменения в Spec Kit, не создавать параллельную карточку TASK.
- **FR-004**: Действующая документация MUST фиксировать независимость xml-generator, роль Host-client как оркестратора и Host-server как авторизации клиентов и маршрутизации, сохраняя неизвестные детали контрактов открытыми.
- **FR-005**: Миграция MUST сохранять предметные правила и доказательства SCADA, прежние пользовательские изменения, код, данные и артефакты; документационная проверка не объявляется проверкой XML-генерации или импорта.

### Scope

Включены правила проекта, конституция, общие инструменты и шаблоны Spec Kit, документационные указатели, ADR и ответы о ролях. Код генерации, API интеграции, схемы БД, запуск SCADA и пересборка EXE не входят в изменение.

### Sources and Open Questions

Источник решения — сообщения владельца от 28.09.2026; [ADR-0009](../../docs/decisions/ADR-0009-unified-spec-kit.md) фиксирует основание. Нерешённых вопросов, блокирующих документационный переход, нет. Q-INT-001/002/003, Q-CTX-001/002 в [реестре](../../docs/06-open-questions.md) сохраняют неизвестные части будущей интеграции и автоматизации.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Проверка общего SDD проходит для пакета и локальных инструментов; все FR-001…FR-005 имеют проверку и доказательство либо явное непроведённое действие.
- **SC-002**: Все 10 исторических TASK-файлов сохраняют исходные SHA256; новые входные правила не требуют создавать TASK-0011.
- **SC-003**: Документационные ссылки текущего изменения разрешаются, а роли трёх продуктов согласованы в точках входа, архитектуре и реестре вопросов.

Реализация: [plan.md](plan.md), [tasks.md](tasks.md). Приёмка определяется [verification.md](verification.md), а не одним статусом `implemented`.
