# План доставки

1. Проверить origin/main и отсутствие чужого расхождения. Просмотреть состав индекса; сохранить существующие изменения и исключения конфигурации, runtime, секретов и артефактов (FR-001, SDD-001/004).
2. Использовать финальный проверенный CSS-кандидат из пакета 004. Сверить SHA256 EXE, ZIP и sidecar, состав ZIP и соответствие встроенного UI текущим исходникам (FR-002, CODE-001/002/003).
3. Создать обычный commit текущего согласованного дерева и отправить main без переписывания истории. Проверить SHA удалённой ветки и файлы через GitHub (FR-001).
4. Опубликовать первый датированный release `v2026.09.29` на этом commit с точными именами assets. В описании указать текущее состояние разработки, ограничения IO/HMI/SCADA. Release доступен через `/releases/latest`, поскольку этот endpoint использует каталог Host (FR-002/004).
5. Запустить настоящий установщик Host с пустым изолированным runtime. Сеть обращается к GitHub, локальных fallback и транспортных подмен нет. Сверить итоговый EXE/provenance и отдельный запуск модуля (FR-003).
6. Записать фактические URL/SHA/результаты; проверить SDD и отправить финальную запись проверки отдельным обычным commit. Релиз остаётся связан с исходным проверенным commit (FR-004).

Публикация выполняется авторизованным GitHub CLI из существующей учётной записи владельца; токены не извлекаются в файлы или вывод. Обычный push сам по себе не является поставкой бинарного модуля.
