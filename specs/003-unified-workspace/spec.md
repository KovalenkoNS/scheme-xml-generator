# Две страницы генератора и единый выпуск по ПЛК

Status: implemented
Updated: 2026-09-29

Приёмка отозвана владельцем 29.09.2026: реализация отклонена из-за структуры, дублирования, пространств имён и неотработанной блокировки антивирусом. Прежние прогоны сохраняются как история, но не подтверждают готовность; исправления и новая проверка обязательны. Реестр: [rejection-audit](../004-semantic-layout/rejection-audit.md).

Источник: прямой запрос владельца полностью пересобрать генератор с двумя страницами и выбором ПЛК → FBD/ST/HMI. Это перестройка интерфейса и сборки с сохранением проверенных алгоритмов XML, а не утверждение о готовой интеграции с DB.

## User Stories

- **US1**: Пользователь открывает основную страницу, видит состояние данных Host и подключённую библиотеку; локальная работа находится на второй странице.
- **US2**: Пользователь загружает свои локальные таблицы, выбирает ПЛК и нужные FBD/ST/HMI, настраивает выбранные области и одним действием получает файлы.
- **US3**: Пользователь получает пересобранное приложение; каталог Host может установить стандартный ZIP без Go SDK.

## Requirements

- **FR-001**: Приложение MUST иметь ровно две страницы: основную для будущего рабочего сценария данных через Host/DB и временную для локальных таблиц. Навигация и детали минимальны; постоянные настройки показывают текущее значение.
- **FR-002**: Главный сценарий MUST быть единым: экземпляр ПЛК и модель715/850 → выбранные выходы FBD/ST/HMI → настройки внутри выходов → выпуск. Самостоятельных страниц по AI/AO/DI/DO или способу генерации нет.
- **FR-003**: Локальный сценарий MUST использовать реальные парсеры XLSX/TXT и генераторы, выпускать данные только выбранного ПЛК, не выдумывать физические ModuleID и показывать реальные ограничения/ошибки и частичный результат. Не заявлять неподдержанные HMI850/DI ST715 как работающие.
- **FR-004**: Подключение XML-библиотеки MUST быть отдельной компактной функцией основной страницы: проверка загружаемой копии, текущие библиотеки и типы/шаблоны; пользовательские исходники не перезаписываются.
- **FR-005**: Тип области РСУ/ПАЗ/СОГО MUST NOT влиять на генерацию или требоваться в форме. Это метаданные инженерного проекта; модель CPU, профиль и реальные входы остаются значимыми. Основная страница не имитирует данные DB, пока не подключён согласованный контракт.
- **FR-006**: Изменение MUST сохранить существующие пользовательские данные, алгоритмы ST/HMI и библиотечные API; пройти применимые проверки и создать Windows EXE/ZIP с SHA256. Прямое уточнение владельца 29.09.2026 «Да, FBD только из библиотеки» отменяет сохранение старых HTTP-маршрутов с фиксированными FBD-шаблонами: они должны отказывать до записи результата/ID с объяснением перехода на библиотеку. Совместимость с импортом SCADA требует отдельной проверки.
- **FR-007**: По уточнению владельца FBD MUST использовать типы, шаблоны, поля и связи подключённой XML-библиотеки, без подстановки жёстко заданного нативного профиля. Инверсия — отдельный переключатель на связи «сигнал → D32», не выбор другого шаблона. NOT является оператором диалекта из предоставленных XML; исходный библиотечный шаблон не изменяется. При отсутствии подходящей BOOL-связи к D32 формирование с инверсией отклоняется до резервирования ID; неоднозначность не разрешается догадкой.
- **FR-008**: Генератор MUST показывать читаемое графическое представление сохранённого результата внутри приложения: FBD-блоки/связи и параметры, HMI-кадры и ST-код. Просмотр открывается из списка файлов без третьей страницы, читает фактический XML и не подменяет его текущим состоянием формы. По отклонению владельца 29.09.2026 автоматическое вмещение тысяч блоков с нечитаемым масштабом запрещено: начальный вид — фрагмент с читаемыми надписями, поиск и переход по сигналу/блоку, отдельная команда обзора всего файла. Параметры не отнимают ширину полотна до запроса пользователя. Недоступная визуальная семантика обозначается; просмотр не считается исполнением/импортом в SCADA.

Изображение владельца уточняет FR-007: DO — один D32 на физический модуль, сигналы на каналах i00…i31, переключаемые NOT на этих связях, Quality канала0 → QUAL_STAT → sts и Ct=0. Типы BOOL/D32/QUAL_STAT и экземпляры выбираются из подключённой библиотеки; аппаратная ссылка Quality и оператор NOT принадлежат отдельному диалекту подтверждённого XML-профиля. Для этого нужен библиотечный модульный сборщик; простого клонирования полного D32 для каждого сигнала недостаточно. Физические ModuleID задаются явно, CPU/драйвер без эталона не объявляется поддержанным.

Уточнение структуры: новые файлы разделяются по ответственности и комментируются, тесты располагаются отдельно. Общая реорганизация всех исходников и проверок вынесена в [004-semantic-layout](../004-semantic-layout/spec.md), чтобы не смешивать изменение поведения с переносом пакетов.

## Acceptance

- По уточнению владельца от 29.09.2026 верификация MUST охватывать **AI + AO + DI + DO**. Для каждого направления проверяются разбор источника, изоляция ПЛК, библиотечный FBD и просмотр сохранённого XML. ST/HMI проверяются по поддержанным CPU/аппаратным профилям; неподдержанные комбинации явно отмечаются, проверка одного направления не заменяет остальные.
- Навигация содержит «Основная» и «Локальные данные»; диалог библиотеки не является третьей страницей.
- Временная страница выпускает выбранные поддержанные выходы одного ПЛК; итог содержит ссылки на файлы и отдельные ошибки, без ложного общего успеха.
- Неподключённая DB явно видна, не подменяется локальным JSON или встроенными демонстрационными данными.
- Новая оболочка проверена в браузере, API — реальными эталонами в изолированном root; изменённые файлы и проверка отражены в verification.md.
