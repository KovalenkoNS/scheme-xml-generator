# Библиотечный DO: один D32 на модуль

Источник: уточнение владельца 29.09.2026 и предоставленное изображение требуемого результата — отдельные BOOL-сигналы проходят через NOT к каналам одного D32 каждого модуля; диагностика Quality канала 0 через QUAL_STAT подключается к `sts`. Это дополняет ограниченный [контракт инверсии отдельного шаблона](inversion.md): клонирование D32 на каждый сигнал не выполняет требование модульной схемы.

## HTTP

`POST /api/generate/library-do`, JSON, та же локальная защита Origin и форма результата, что у `/api/generate`:

```json
{
  "templateKey": "ключ выбранного DIO-1 из GET /api/templates",
  "plcName": "1001",
  "context": {"controllerTypeName": "TENIX-CPU850"},
  "physicalProfile": "measurement-quality",
  "fileName": "DO_1001.xml",
  "pous": [{
    "name": "DO_A13",
    "groupId": 100,
    "pouNumber": 1,
    "modules": [{
      "name": "A13-01",
      "id": 17,
      "channels": [{"channel": 0, "tag": "_1001_SIGNAL_DDVH", "invert": true}]
    }]
  }]
}
```

Числа и имена в примере синтетические. `id` — обязательный фактический ModuleID, значение 0 допустимо; приложение не подставляет его из примера. `tag` — точное имя BOOL-переменной; суффикс `_DDVH` сервер сам не добавляет. Имя экземпляра модуля: `_<plcName>_<name с '-'→'_'>`, согласовано с существующим ST. Пропущенные каналы не уплотняются и не заполняются вымышленными сигналами; пустой резервный модуль допустим. Одна POU может содержать несколько модулей.

`context` использует `GenerationContext`: CPU обязателен для определения профиля, необязательные `version`, `project`, `controllerId`, `resourceId` перекрывают текущую конфигурацию только на один запрос. `groupId` и `pouNumber` необязательны; без них используется настройка приложения, номера POU увеличиваются последовательно. `physicalProfile` при пропуске равен `measurement-quality`; этот аппаратный слой подтверждён только для CPU850, CPU715 здесь отклоняется. ST/HMI и библиотечные API сохраняются. По XML-002 прежние HTTP-режимы со встроенными FBD-шаблонами отключены и возвращают `410` до выделения ID и записи файла.

## Источники и границы

- Выбранная подключённая библиотека должна содержать шаблон с одним D32V_v1 и одним образцом связанного BOOL-сигнала. Из него берутся реальные ISA-номера, библиотека, исходные значения карточек и сигнатуры. Поддержанный пример — `DIO-1`, ID 12772 в пользовательской all_lb_sinopec.xml; ID библиотеки не закреплён в коде.
- QUAL_STAT разрешается по примитивам **той же** библиотеки; отсутствие или противоречие определений даёт отказ. Нет подстановки `17611/TenixRtLib` вместо отсутствующей библиотеки.
- NOT `35/-32`, порты `0/Result`, и физический драйвер `38/6127`, поле `.Quality` канала 0 DO32P, взяты из предоставленного `DO_FBD_example.xml`. Это операторы и аппаратный профиль XML-диалекта; они не подменяют пользовательские шаблоны. Привязка `_IO_I<ModuleID>_DO32P_0_VAL_DIAG` использует введённый ID.
- В модуле создаётся один D32. Каждое указанное значение подключается к своему `i00…i31` прямо либо через отдельный NOT по `invert`. `.Quality → QUAL_STAT.QUAL`, `QUAL_STAT.Result → D32.sts` создаются один раз на модуль; `Ct0` не получает вымышленного источника.

Базовые затраты на модуль: 3 блока и 2 связи. Каждый сигнал: BOOL и связь (2 T11), с инверсией ещё NOT и дополнительная связь (+2 T11). Одинаковые имена BOOL могут использовать общую карточку; имена аппаратных/модульных карточек не могут конфликтовать с сигналами. Подготовка проверяет дубликаты физических ID, входов, имён POU и диапазоны до изменения allocator. Сериализация и геометрия переиспользуют существующий модульный renderer. Старый native850 сохранён только как внутренний алгоритм с историческими регрессионными проверками; доступного HTTP-режима с фиксированным шаблоном нет.

Приёмка: 32 сигнала → один D32, 32 необязательных NOT и одна диагностическая цепь; второй модуль создаёт второй D32 с независимыми каналами. Проверяются смешанная инверсия, реальные библиотечные ISA-номера, отсутствие библиотеки/QUAL_STAT, отказ до записи и точный расход ID. Это структурная проверка; импорт и выполнение SCADA не заявляются.
