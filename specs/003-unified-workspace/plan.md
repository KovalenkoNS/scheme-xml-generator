# План

1. Сохранить существующие генераторы и форматы API; заменить пользовательскую оболочку на две страницы с единым состоянием выбранного ПЛК, выходов и локальных источников. После проверки замены убрать неподключённые старые JS-контроллеры и тесты их прежнего DOM из продуктового дерева. Их точная копия с текущими незакоммиченными изменениями сохранена в `.artifacts/retired-web-20260929`; backend-проверки старых API сохраняются. Новые проверки относятся к действующему интерфейсу.
2. Основная страница показывает маршрут Host → server → DB и состояние подключения; неподключённый контракт не выдаётся за рабочую генерацию из БД. Локальная страница принимает XLSX/TXT, определяет доступные ПЛК и поддержанные профили по реальному предварительному разбору. Один запуск выпускает выбранные FBD/ST/HMI с отдельными результатами и явными ошибками.
3. Физические ModuleID и транспортный контекст настраиваются внутри выбранных областей. Не выводить ModuleID из позиции или имени. Тип системы РСУ/ПАЗ/СОГО не запрашивается и не участвует в генерации. Ограничения текущих XML-профилей CPU сохраняются и объясняются.
4. Подключение XML-библиотеки вынести в диалог основной страницы: импорт копии с проверкой, каталог типов/шаблонов, текущее значение. Не перезаписывать пользовательские исходники.
5. Проверить реальные API локальными эталонами в изолированном root: обязательная матрица AI + AO + DI + DO для источников, библиотечного FBD и просмотра сохранённого файла. Отдельно проверять ST/HMI по поддержанным профилям, выбор ПЛК/выходов, ошибки/частичный выпуск, импорт библиотек и отсутствие ложной DB-готовности; браузерная проверка двух страниц и сборка EXE/ZIP+SHA256 для каталога Host. Импорт SCADA не заявлять.
6. Новый FBD использует общий `/api/generate` с явно выбранными `templateKey` каталога, а не прежние hardcoded AO/SKZ FBD-обработчики. Отдельный `SignalRequest.invert` клонирует выбранный шаблон и вставляет оператор NOT только на обнаруженные библиотечные BOOL→D32.iNN связи; сохраняет type IDs/карточки/остальные связи. Подсчёт ID использует подготовленный клон; отказ происходит до выделения ID. Поддержку проверяет реальный DIO-1 шаблон библиотеки и отрицательные примеры.
7. Для целевого DO-графа по изображению использовать отдельный библиотечный сборщик `/api/generate/library-do`: один D32 на модуль, реальная нумерация каналов, BOOL→optional NOT→D32, Quality→QUAL_STAT→sts. При отсутствии требуемых библиотечных метаданных — отказ без fallback. Источник аппаратной ссылки — существующий XML-профиль850, отдельно от библиотеки типов.
8. Добавить изолированный компонент `web/preview/`: парсер полученного XML и диалог SVG/текста, POU/кадры, масштабирование и просмотр параметров. Никакого выполнения XML/скриптов, внешних URL или рендеринга HTML из данных; только безопасные графические примитивы и текст.

## Обязательные правила

Уточнение владельца 29.09.2026 после сообщения о конфликте XML-002 и прежнего FR-006: старые HTTP-сценарии FBD с фиксированными шаблонами полностью отключить. Это исключает их из пункта1 о совместимости API; ST/HMI и библиотечные маршруты остаются. Отказ проверяется до резервирования ID/создания файла; фиксированный FBD не используется как fallback.

Проверка FR-006/FR-007 включает прежнее `pous[].io.modules` в общем `/api/generate`: этот формат добавлял фиксированные аппаратные блоки и назначал отсутствующие ModuleID. HTTP отклоняет любую ненулевую секцию `io` с `410` до нормализации, разрешения шаблонов, allocator и записи файла. Сохраняются одиночные библиотечные запросы, `pous[].signals` и `/api/generate/library-do` с явными ModuleID. Регрессия проверяет AI/AO/DI/DO, явный/отсутствующий ID, смешанный документ и неизменность ранее созданных allocator/output.

Применяются [правила SDD](../../.specify/memory/rules.md): SDD-001…003, CODE-001/CODE-001-T/CODE-002/CODE-003, ARCH-001, DATA-001, PLC-001, UI-001 и XML-001…006. CODE-001 проверяется фактической картой `web/{shell,shared,sources,library,generation/{fbd,st,hmi},preview}` и отдельными `tests/web`, `tests/preview`, `tests/support`. Смешанные общие файлы не сохраняются под новым именем. Все функции компонентов имеют краткие предметные комментарии. Остаточное нарушение — FAIL, завершение и verified запрещены. Реорганизация Go и общий проверяющий инструмент принадлежат пакету004.

При большом IO-листе расположение обычных FBD-экземпляров рассчитывается из реальных `layout` границ выбранного библиотечного шаблона: столбцы не перекрываются, координаты ограничены контрактом XML. Модульные DO используют самостоятельный API и диапазон POUNum; отсутствие физических ID — ошибка, не автоматическое заполнение.
